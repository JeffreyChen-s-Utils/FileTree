## U-20260926-08 · 2026-09-26 · Stop takes effect at once; live-scan tests no longer depend on timing · #incident #scanner #tests

- **What happened**: CI on Windows / Python 3.14 failed `test_stopping_keeps_what_was_read` once (run 36168469709): the scan finished before Stop took effect, so the result was complete instead of partial. Two causes. The test depended on sleeps (a slow runner reached Stop late). And the scanner itself noticed Stop only when its calling thread next woke up — up to one progress interval (0.1 s) — while the worker threads kept taking new folders.
- **Fix**: the worker threads now watch the cancel event and take no new folder once it is set; the calling thread stops waiting and raises `ScanCancelledError` after the workers finish the folders already in hand (`_Crawler._take`, `_Crawler.run`). The two live-scan GUI tests hold every folder but the root behind a gate the test opens, with one worker, so "still running when Stop arrives" is guaranteed instead of likely; six runs in a row pass.
- **Files**: `file_tree/core/scanner.py`, `test/test_gui.py`.

## U-20260926-14 · 2026-09-26 · Size on disk for every entry · #done #core #gui #perf

- **What**: `progress.md` #2. Every entry has its size on disk (`Node.allocated`, what TreeSize calls allocated space): an **On disk** column in the folder tree next to Size, "16.7 GB (16.7 GB on disk)" in the summary line, and `allocated_bytes` / `allocated` in the CSV and JSON exports. Moving to the Recycle Bin and rescanning a folder keep it right up the chain.
- **Measured first** (D:\Codes, 766,000 entries): asking Windows per file (`GetCompressedFileSizeW`) cost 100-145 µs per file, several times the whole scan's cost per file, so it is not used for ordinary files. Listing folders with `NtQueryDirectoryFile` (which returns allocation with the listing) was 30 % slower than `os.scandir` in Python (15.2 s against 11.8 s, one thread), so the scan keeps `os.scandir`. Rounding each ordinary file up to the volume's clusters came within 0.64 % of the exact total (tiny files kept inside the MFT take no cluster). No compressed, sparse or cloud-only file was among the 766,000, so the exact calls cost nothing there.
- **Rule** (`file_tree/core/allocation.py`): POSIX `st_blocks` × 512 (exact, from the stat the scan makes anyway). Windows: ordinary files rounded up to clusters (`GetDiskFreeSpaceW` on the volume of the scanned folder, 4096 when it cannot be told); compressed or sparse files asked for exactly; offline and cloud placeholder files (recall on open / on data access) count 0 and are never opened, so nothing is downloaded.
- **Cost** (median of five scans each, A/B against the previous commit): 6.93 → 7.12 s (+2.7 %), +17.5 bytes per entry. Sizes of up to 1,024 clusters are handed out from a table so equal values share one int object; before that the scan was 5-9 % slower and each entry 44 bytes bigger.
- **Layout**: with seven columns the names were cut short, so the tree's fixed columns are narrower and the tree gets 650 of 1,100 splitter units (was 600).
- **Files**: `file_tree/core/allocation.py` (new), `file_tree/core/{node,scanner,export}.py`, `file_tree/gui/{tree_model,results_view,strings}.py`, `tools/make_screenshots.py`, `test/test_allocation.py` (new), `test/test_core.py`, `test/test_gui.py`, `README.md`, `README/README_zh-*.md`, `docs/images/main_window_*.png`, `architecture.md`.

## U-20260926-17 · 2026-09-26 · Find duplicate files and move the extra copies to the Recycle Bin · #done #core #gui #perf

- **What**: `progress.md` #12. A **Duplicates** tab: *Find duplicates* groups files with the same content anywhere in the scan. Each group reads "3 copies of 2.9 MB — 5.7 MB in extra copies" over its files, oldest first; *Select extra copies* selects all but the oldest of every group, and Delete (or the context menu) moves them to the Recycle Bin with one question. The groups follow the tree: pruned after a move to the Recycle Bin or a folder rescan, dropped on a new scan. Up to 1,000 groups are listed, the most extra space first; the summary line counts all of them and the files that could not be read.
- **How** (`je_file_tree/core/duplicates.py`, Qt-free): same size (no reading), then a BLAKE2b hash of the first 64 KB, then of the whole file, each round only among files the round before left together; hard links (same `st_dev` and `st_ino`) count once; empty files, links and unreadable files are left out. Reading runs on a pool of 4 threads; `DuplicatesWorker` passes progress on at most ten times a second, and Stop is checked before every file and every 1 MB.
- **Measured** on D:\Codes (766,000 entries): 619,000 files share a size with another one, and one thread had not finished even the 64 KB heads after ten minutes, so files under 1 MB are left out by default (a list offers any size, 100 KB, 1 MB, 10 MB, 100 MB). From 1 MB: 1,785 candidates, 3,496 reads, 10.1 GB read, 421 groups with 7.64 GB in extra copies; 73 s the first time (cold cache, one thread), then 24 s with one thread against 7 s with four.
