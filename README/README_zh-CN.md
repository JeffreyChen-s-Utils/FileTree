# FileTree

**看看磁盘空间都用到哪里去了。** FileTree 会扫描一个文件夹或整个磁盘，把里面每个文件的大小加总，先列出最大的文件夹和文件——用文件夹树、彩色的方块图和最大文件列表呈现。找到不需要的东西时，直接在窗口里把它移到回收站。

**选项 → 测量 Windows 逐文件磁盘大小** 默认关闭，应用到后续完整／分支扫描，启用后请重新扫描。此功能以不跟随链接的元数据句柄查询 `FILE_STANDARD_INFO`，核对完整的 64 位卷／128 位文件标识（Python 3.12 之前使用旧版 stat 标识）、大小与修改时间；即使未显示普通压缩标志，也能测量普通文件与 XPRESS／WOF 的分配大小。已知云端／离线文件仍不查询并记为零，不支持、权限不足或记录已变化时采用已说明的大小估计值。逐文件查询会增加扫描时间，不读取文件内容；共享数据区段与文件夹元数据仍未知，硬链接仍按各名称计算。默认扫描对普通文件保留簇估计值。原生自建测试文件通过 NTFS／XPRESS8K 压缩及解压缩内容核对，逐文件测量的重新扫描记录了 2 MiB XPRESS 文件的 73,728 字节分配大小，该文件未显示普通压缩标志。

Windows 已扫描文件夹的右键菜单提供 **NTFS 压缩估算…**。可取消的只读后台任务检查已记录的日志、文本、代码与可能未压缩的图像类型，显示最大的 1,000 个候选项及全部数量、逻辑大小／具名磁盘分配，并查询文件系统与分配单位。可能节省量限制在 **0–候选项的磁盘分配**，不预测固定压缩率：扩展名不能证明可压缩程度，具名磁盘分配可能是估计值或由硬链接共享。隐藏／系统、压缩／稀疏、重解析／云端／离线及元数据未知的项不列为候选，不完整范围会有标示。此预览不读取文件内容，也不执行压缩命令。双击选择原始记录的文件，Ctrl+C 复制列表，停止／关闭会丢弃已取消响应并等待后台任务。原生压缩／解压缩操作仍待完成；预览会明确显示未知／非 NTFS 范围。

**用户** 标签页按整份扫描的文件所有者累加，显示最大的 1,000 组，并保留全部分组／文件／字节数，列含逻辑大小、具名磁盘分配、文件数及逻辑大小占比。POSIX uid 使用扫描已读取的 stat；Windows 的 **选项 → 记录 Windows 文件所有者** 因逐文件安全性查询成本较高而默认关闭，启用后请重新扫描，设置应用到后续完整／分支扫描。共享不可变的 uid／SID 标识增加一个所有者字段（测量每个节点增加 8 字节）。Windows 只读查询普通文件的所有者 SID，跳过链接及云端／离线文件，查询后重新核对记录的元数据。未启用、无权限、缺少或已变化的所有者独立列为 **所有者未知**，扫描不完整也会标示未读取数据。打开标签页才会在可取消的后台任务累加并查询账户名称，名称无法解析时保留 uid／SID。停止、切换标签页、新扫描及关闭会丢弃已取消响应，关闭等待所有任务结束；移动及分支重新扫描会使总计失效。**刷新记录总计** 仅重新汇总扫描，所有者已变化时请重新扫描。支持 Ctrl+C 与当前列表 CSV 导出。文件夹所有者不会应用到其中的文件，硬链接仍按各名称计算，磁盘分配仍为估计值。所有者不能证明实际使用或移除权限，此标签页不会生成清理操作。仅含文件夹的 JSON／历史记录不保存文件所有者。

**选项 → 记录文件访问／创建时间** 默认关闭，适用于之后的完整与分支扫描；开启后请重新扫描。沿用已读取的 stat，每个普通文件快照增加 16 bytes，不新增 Node 字段或额外时间查询。文件夹树标题菜单提供默认隐藏的“记录的访问时间”与“创建时间”列。**文件 → 文件时间…** 可按记录的访问／创建时间，筛选至少多少天前的文件（0–36,500 天，默认 730）；显示最大的 1,000 个符合条目，以及全部符合数量、字节与未知数量，支持 Ctrl+C、选中树中对应条目、停止与关闭后等待后台任务结束。整棵树的筛选在工作线程进行。缺少或在未来的时间保持未知；不记录文件夹与链接时间。创建时间取 birthtime（旧版 Windows Python 缺少 birthtime 时才用 ctime），不使用 POSIX ctime。只读查询 NTFS `NtfsDisableLastAccessUpdate`，包含初始化与系统管理标志；报告停用或配置未知时，无法按访问时间筛选，仍可按创建时间筛选。注册表值可能需重启，且无法证明每个磁盘实际采用的配置。其他文件系统／提供者也可能延迟或停用 atime，后台读取也会改变日期，记录时间无法证明实际使用时间。此视图不会准备清理操作。最大文件 CSV 新增 `accessed`／`created` ISO 日期，未知时留空；仅含文件夹的 JSON／历史不保存文件时间。

扫描栏的“**暂停／继续**”会暂停获取新文件夹。当前文件夹读取会完成，文件夹树仍持续更新；暂停时仍可“停止”或关闭窗口。最后的结果分析不能暂停。经过时间包含暂停期间，继续时保留同一份扫描及计数。

“**选项 → 低优先级扫描**”默认关闭，应用到新扫描。每个扫描线程使用 Windows 后台 CPU／I/O 模式，或 Linux nice 10 与最低的 best-effort I/O 优先级，不影响界面线程。不支持的平台、权限拒绝或仅部分应用会报告；可读文件夹仍继续扫描。I/O 效果取决于磁盘调度器，扫描可能花费较长时间。命令行及测量工具接受 `--gentle`，命令行 JSON 包含 `warnings`。

矩形树图与旭日图共用“**颜色 → 按修改年龄**”，使用“年龄”列表的范围，并显示由浅（近期）到深（较旧）的图例。颜色按扫描／分析时间计算，鼠标移动时不会随时钟改变。文件夹按最新修改记录着色；无可用日期、未来日期与合并的小项目为灰色。这表示修改年龄，不能判断最后访问时间或是否未使用。

“**文件 → 导出**”与图表右键菜单可将屏幕上的图表保存为 **PNG**，包含当前可见范围、配色及选择状态。条形图与旭日图另提供 **SVG**：有数量上限的完整条形行或圆弧会绘制成矢量图形与文字，不使用旭日图的缓存位图。PNG 编码与文件写入由导出线程处理，以原子方式替换文件；关闭窗口会等待导出完成。

“**文件 → 打印当前视图**”（`Ctrl+P`）会打开系统打印对话框。“**文件 → 导出 → 当前视图（PDF）**”会保存一页 A4，按捕获的视图选择横向／纵向。两者将当前标签页及可见范围等结果等比例放入可打印边界，不拉伸或裁剪；输出是捕获的像素，滚动范围外的项目不在其中。PDF 由导出线程使用 Qt PDF 引擎写入，以原子方式替换指定文件；关闭窗口会等待完成。

图表页提供可点击的文件夹路径与 **返回／前进**（`Alt+Left`／`Alt+Right`）。历史保留当前扫描最近 100 次浏览；返回后打开其他文件夹会替换前进历史。新扫描会重置历史，重新扫描会移除失效条目。长路径可水平滚动，**…** 可选择更上级的文件夹。

展开文件夹树下的 **详细信息**，可查看选中条目的大小、磁盘大小、文件与文件夹数、已记录的修改日期，以及小型类型与文件年龄分布。面板会记住展开状态；扫描结束且面板展开时才在可取消的后台任务中计算分布，仅使用已读取条目，未知与未来日期单独列出。更换选中条目会丢弃过期结果，关闭窗口会等待任务结束。

**文件 → 导出 → 当前列表（CSV）** 可保存搜索、重复文件、变更、文件类型、文件新旧、最大的文件、清理建议或问题列表，保留显示的标签、单位、筛选与排序。分组列表包含组标题及其条目，即使已折叠也是如此。列表或文件夹树获得焦点时，**Ctrl+C** 会将选中行与列名复制成带引号的制表符分隔文本；文本框仍正常复制。看似公式的文本会加上电子表格保护前缀。CSV 获取会以短批次让出界面，通过有上限的队列交给后台任务原子写入；列表变更会取消导出并保留已有目标文件。

在 **文件类型** 双击扩展名，即可同时查看最大的匹配文件与最多 1,000 个 **所在文件夹**，包含匹配类型的大小、文件数及占全部匹配字节的比例。文件夹仅统计直接包含的文件，嵌套文件夹不会重复计算。两份列表在可取消的后台任务中一起计算，并遵循 **仅选中的文件夹** 范围。变更扩展名、扫描或范围会丢弃旧结果；**显示全部** 可返回普通列表。按文件年龄查看文件也在后台运行。

Windows 的 **详细信息** 会解释休眠、分页与交换文件、Windows.old、回收站、System Volume Information、WinSxS、Windows 更新下载及传递优化缓存。识别使用磁盘根目录或当前 Windows 安装的完整位置，包含其子条目，不会仅凭同名判断。按钮打开对应的 Windows 设置或系统工具；FileTree 不执行清理命令，也不移动这些系统管理条目。操作后台任务也会拒绝包含它们的文件夹，并重新检查解析后的路径。WinSxS 汇总可能包含共用硬链接；未读取的系统数据仍未知。

四种图表提供辅助工具名称、键盘操作说明，以及当前文件夹与选中条目的已记录大小及数量。用 Tab 或点击将焦点移至图表：**方向键** 选择已绘制条目，**Enter** 打开选中的文件夹，**Backspace** 返回上级。树形图保留上／下选择卡片及右／左展开、折叠的操作；条形图与树形图会将选中行滚动至可见位置。导航使用有上限的图表布局，合并或未显示的条目可在文件夹树查看。Alt+Left 等组合快捷键保持原有操作。

**查看 → 主题 → 系统／浅色／深色** 可立即切换并记住选择。系统模式恢复原生平台样式与调色板；指定主题使用一致的 Qt 控件，以及清晰的文字、选中与禁用颜色。调色板或样式变更会重新绘制图表。矩形树图与放射图按实际填色对比选择黑字或白字；矩形树图仅在渐变两端都维持至少 4.5:1 对比时保留渐变。条形图的名称与数值使用当前调色板，显示在彩色条形之外。

## 功能

**选项 → 扫描线程数…** 设置新扫描与分支重新扫描的并行数，范围 1–32；现有默认值仍最多为 4（按 CPU 数量限制），保存值无效时采用默认值。进行中的扫描保留原线程数。慢速共享可能受益于较高并行数，但磁盘／服务器在过高负载下也可能变慢，请按环境选择。Windows 可粘贴 `\\server\share` 等绝对 UNC 路径，以当前账户权限访问。权限不足／断线的分支保持不完整，欢迎页包含此提示。目前没有共享环境，实际 UNC／网络驱动器性能、分配与断线验证仍待完成。

欢迎页、清理页或视图菜单的 **回收站…** 可检查各磁盘总量。Windows 可选中一个本地磁盘，再点 **清空选中磁盘的回收站…**。两次询问均列出磁盘、报告大小与项数，并说明永久移除。后台任务重新查询总量，拒绝总量已变化或记录不完整的回收站，再针对明确磁盘调用 `SHEmptyRecycleBinW`。这项永久移除例外仅限当前用户的系统回收站，不接受任意路径或所有磁盘范围。原生清空操作开始后不能取消，完成前禁用停止／关闭与项的激活。系统操作期间新增的项也可能被移除。错误可能留下部分已清空的回收站，会结合重新查询的总量显示。完成后更新容量／回收站元数据；重新扫描可更新主树。此对话框的 Linux／macOS 功能仍为只读，清空流程仍待完成。验证不会清空真实用户的回收站。

欢迎页在每个就绪磁盘下显示回收站大小／项数，清理页显示当前扫描所在磁盘。标示起初为 **尚未查询**；**刷新回收站大小** 会在可取消的后台任务查询只读快照（最多 256 个就绪根目录，优先查询扫描所在磁盘），移至回收站后或关闭回收站管理窗口也会刷新。缺少范围保持未查询；部分失败显示 **总计未知**、已知大小／数量与纯文本错误，不会当作空回收站。POSIX 大小为内容的逻辑字节，范围可能重叠，请勿累加。大小单位与语言会随设置刷新。新的完整扫描会丢弃未完成响应并重置清理页范围，关闭程序会等待查询结束。这些标示不会生成清理建议或更改扫描记录。

**视图 → 磁盘总览…** 或欢迎页的 **磁盘总览…** 列出最多 256 个就绪的已挂载磁盘与全部数量，包括文件系统、总量／已用容量、可用空间条、分配单位、回收站大小与项数。双击扫描根目录；Ctrl+C 复制行。可停止的后台任务更新系统数值与查询回收站，不读取内容、不修改项。可用空间可能扣除保留量／配额；重复挂载可能共用容量，不能汇总各行。Windows 簇查询失败会保持未知，不采用扫描器的估计替代值。POSIX 单位使用文件系统片段，不采用 Qt 的最佳传输块大小。Windows 回收站总量来自 `SHQueryRecycleBinW`；Linux 覆盖主目录 freedesktop 回收站与挂载根目录的用户回收站，macOS 使用个人 `.Trash`／`.Trashes`。POSIX 大小为逻辑内容字节，不含文件夹／回执元数据与共享分配；失败显示总量未知及已知大小。macOS 原生验证仍待完成。停止／关闭会等待当前系统调用与后台任务，丢弃取消后的响应。清空回收站是此只读总览之外的功能。

**文件 → 导出 → 扫描报告（HTML／Excel）** 经可停止的模态后台任务保存整份扫描记录，不受当前筛选与图表浏览位置影响。两种格式均含摘要／扫描范围、最大文件夹、最大文件、扩展名、分类与修改时间列表，标题显示已列出／全部数量。最大文件夹范围重叠；大小／数量保留原始字节与数字，磁盘分配仍是估计值，范围不完整时有标记。文件夹／文件各保留 1,000 条，扩展名限 10,000 条。HTML 内嵌整份根目录的矩形树图、条形图与旭日图 PNG 截图，图形范围有限；没有脚本、外部资源或网络请求。Excel 每份列表各用一张工作表，含冻结标题与筛选，转义公式样式文本与 XML 控制字符，每格限 32,767 字符，16 位以上整数以精确文本保存。成功原子替换前，停止／关闭保留现有目标。`openpyxl` 是安装时包含的应用依赖包；生成报告不读取原始文件内容。

**文件 → 项目与可重建数据…** 在可停止的后台任务检查已扫描数据，保留最大的 1,000 个项目与管理存储区，并显示全部数量。已知逻辑大小分成 **源文件／其他**、`.git` 与 **可重建数据**，另列已记录的磁盘分配与扫描范围。源文件／其他包含未分类数据；嵌套项目范围重叠，不能汇总各行。Git 指针文件不含外部元数据。Python／conda 环境标记与项目清单共用清理的保守识别规则，覆盖环境、`node_modules`、Rust 输出与项目内 Gradle 数据。双击在树中选中项目；Ctrl+C 复制行。**检查符合条件的可重建项** 将最多 1,000 个项送入现有回收站检查流程，遵守最短时间、扫描范围、规则设置与排除条件。已停止的扫描不提供清理建议。生成数据可能含自定义文件，需人工检查。独立环境、Maven `.m2`、全局 Gradle 缓存与 Docker 数据分开识别，不假定可丢弃；不执行缓存清除或 Docker 命令。

**文件 → Git 历史…** 用 `git rev-list --objects --all --no-object-names` 和 `git cat-file --batch-check` 检查选中的工作文件夹（或选中文件所在的文件夹），适合 `.git` 占据项目主要空间时使用。可停止、限时 120 秒的后台任务保留最大 1,000 个可达对象的标识、类型与 **解压后长度**，并显示全部数量；有界管道避免将整份历史存入内存。Ctrl+C 复制行。`git count-objects -v` 识别 gc 可能合并的松散对象，但所有引用可达的对象会保留，实际节省量仍未知。保留 Git 所有者检查；禁用可选锁定、自动维护、文件系统监视钩子与延迟下载。不修改仓库数据、不执行 gc，也不下载缺少的对象。需安装支持 `--no-lazy-fetch` 的 Git；缺少或较旧版本会报告错误。Git 名称提示可能有歧义且会更改换行，因此不列对象名称。

树状列表上方的 **筛选已展开的文件夹…** 仅在已展开的文件夹下匹配名称，不区分大小写。可取消的后台查询保留匹配项目及其上层路径，不搜索折叠的内容。清除输入框即可恢复树状列表与展开状态。从图表／列表选择被隐藏的目标会清除筛选，以显示目标。源／代理索引映射保留选择、排序、持久索引及实时更新；总量、图表与导出仍使用完整扫描。

**文件 → 比较两个文件夹…** 以温和后台任务独立扫描两个现有文件夹，显示完全匹配的相对路径、仅左／右侧有的项目、类型／大小／时间差异及两侧元数据。Unicode 与大小写完全匹配；不跟随链接，无法读取文件夹下缺少的项目仍为未知。元数据相同仍是 **尚未验证内容**。选中文件对后点击 **验证选中的内容**，可停止完整哈希验证，并以快照防止更改造成误判；更改、读取错误与已知云端占位符保持无法验证。哈希结果对应验证当时。Ctrl+C 与原子 CSV 导出涵盖显示的行（最多 10,000 行，并显示全部数量及不完整范围）。比较为只读，不提供同步操作。

**文件 → 云端与特殊文件…** 在可停止的后台任务查阅已记录元数据，显示最大的 1,000 个匹配项目及全部匹配项目的数量／总量。召回／脱机属性可能来自 OneDrive、Dropbox 或其他服务，提供者与本机内容比例未知。**完整内容大小** 是含在线内容的逻辑长度，下载后的分配仍未知。列表也识别 Windows 压缩／稀疏属性；没有属性却分配较少时，原因保持未知（可能是稀疏、压缩或驻留数据）。召回／脱机的分配 0 是扫描估计。界面显示不完整范围及无法获取的元数据，不打开／下载内容，也不增加每个扫描项目的字段；支持排序、Ctrl+C 及双击选择树状列表中的项目。

Windows 可用 `python tools/measure_streams.py <folder> --entries 10000 --repeats 5` 独立测量 NTFS 备用数据流。工具先计时扫描整个文件夹，再对有限数量的文件与文件夹查询额外元数据，输出 JSON。排除重解析点，失败保持未知，不打开数据流内容；数据流长度是逻辑字节，不是磁盘分配。2026-10-07 源码文件夹样本的 9,749 个项目均未发现备用数据流；额外查询耗时 1.694 秒，普通扫描 0.466 秒（五次中位数，含每项目两次标识检查）。这个样本不能代表整盘出现比例；普通扫描保持原有行为。

Windows 可用 **选项 → 资源管理器集成…**，在自己账户的资源管理器文件夹菜单添加或移除 **使用 FileTree 扫描**（Windows 11：**显示更多选项**）。保存前不会启用，不需要管理员权限，且不会覆盖或移除没有专属标记的注册项。移动可执行文件或源码文件夹后，请重新注册。命令使用加上引号的绝对启动路径，因此源码版本也可从资源管理器的工作目录启动。Windows 上的 FileTree 项目右键菜单也提供原生 **属性** 对话框。

- **点一下就开始**：选一个文件夹、点一下磁盘、把文件夹拖到窗口上，或粘贴路径。
- **并行、边扫边看**：同时读取多个文件夹；两个工作线程记录文件身份时，约 202 万项的 Windows 系统盘耗时 208 秒。扫描时文件夹树就会陆续出现，最大的文件夹排在最前面；点击停止会留下已经读到的部分。
- **文件夹树**：从大到小排列，每一行有它实际占用的磁盘空间、显示它占所在文件夹比例的条形，还有文件数、文件夹数与里面最近一次变动的时间。
- **图表**，四种看文件夹的方式，在选项卡角落切换（一开始是方块图）：**方块图**（每个文件一个方块，大小代表占用的空间；文件夹里小到看不见的文件合成一个斜线方块）、**条形图**（文件夹里每个项目一个条形，从大到小，附大小与比例）、**旭日图**（当前文件夹在中心，每深一层就是外面一圈）和**树状图**（可展开的文件夹分支，每张卡片附大小与比例）。单击可以在文件夹树中找到它，双击可以聚焦文件夹，四种图会一起跟着。
- **最大的文件**：整个扫描范围内最大的 1,000 个文件，附筛选框。
- **搜索**（Ctrl+F）：按名称，或 `*.mp4` 这类模式，在整个扫描范围内找文件和文件夹。
- **清理**：列出通常可以删掉的东西——临时文件、浏览器缓存、崩溃转储、包缓存、可以重新构建的构建产物、下载文件夹里的旧安装包、空文件夹——按种类分组，并说明删掉各种东西的影响。
- **重复文件**（在“清理”里）：把内容相同的文件分组，并显示多余的副本占了多少空间；明确选择保留副本后，即可选中多余的副本并移到回收站。
- **与之前的扫描比较**：把扫描保存为 JSON，之后就能看出哪些文件夹变大、变小、新增或消失。
- **文件类型**与**文件新旧**：按扩展名与种类（图片、视频、压缩包…），以及按最后修改时间统计占用的空间；双击一行就列出它最大的文件。
- **安全地释放空间**：“移到回收站”每次都会先询问，不会永久删除；移动前会在后台核对项目，之后重新扫描受影响的文件夹。
- **导出**文件夹列表或最大的文件为 CSV（可用 Excel 打开），或把文件夹树导出为 JSON。
- **English、繁體中文、简体中文**，随时切换；内置“使用说明”。
- 链接与目录联接会列出来，但不会进入计算，所以不会重复计算，链接形成的循环也不会让扫描停不下来。无法读取的文件夹列在“无法读取”标签页，不会中断扫描。

## 安装

FileTree 可在 Windows、macOS 与 Linux 上运行。

**Windows，不需要 Python**：从 [Releases](https://github.com/JeffreyChen-s-Utils/FileTree/releases) 页面下载 `FileTree-<版本>.exe` 直接运行，不必安装。

从下一次发布起，同一页也会提供 `FileTree-<版本>-windows-standalone.zip`。解压**整个文件夹**后运行其中的 `FileTree.exe`，启动较快；DLL、插件及翻译文件都要保留在旁边。单文件 EXE 较方便携带，但每次启动都会先解压内含文件。两种形式都不需要 Python。

**有 Python 3.10 或更新版本**，从 PyPI 安装：

```bash
pip install je_file_tree
je-file-tree
```

或从源代码运行：

```bash
git clone https://github.com/JeffreyChen-s-Utils/FileTree.git
cd FileTree
pip install -r requirements.txt
python start_file_tree.py
```

`python -m je_file_tree` 的效果相同。

### 编译成独立程序

要把 FileTree 给没有安装 Python 的人使用，可以用 Nuitka 编译成程序文件夹或单个 `.exe`：命令与每个选项的用途请见 [nuitka.zh-CN.md](../nuitka.zh-CN.md)。

## 使用方法

1. **选择要扫描的地方**：在起始页点“选择文件夹…”或其中一个磁盘、把文件夹拖到窗口上，或在上方的输入框输入路径后按 Enter。也可以从命令行直接开始扫描：`je-file-tree D:\Projects`（或 `python start_file_tree.py D:\Projects`）。
   拖动文件夹会在原位置扫描，且只接受复制操作；即使用 Shift 请求移动，也会保留来源。
2. **边扫边看**：文件夹树会立刻出现，FileTree 一边加总，最大的文件夹一边往上排；最大的文件与文件类型在扫描结束时补上。随时可以点“停止”（或按 Esc）结束扫描，已经读到的部分会留下来并标示为不完整。
3. **找出占空间的东西**：最大的文件夹排在最上面。点文件夹旁的箭头看里面的内容，或在右边的图表里浏览。

### 看懂结果

| 位置 | 告诉你什么 |
|---|---|
| 文件夹树 | 大小、“占用空间”（实际占用的空间：按整个簇计算，通常比大小多一点；压缩文件较少，只在云端的文件是 0）、“占上级比例”（占上一级文件夹的比例）、里面的文件数与文件夹数、最近一次变动的时间 |
| 图表 | “方块图”：每个文件一个方块，大小代表占用的空间；每个文件夹顶部有名称和大小。太小的文件合并成灰色斜线方块。“层数”决定显示深度，“颜色”可按文件类型或文件夹上色。“条形图”：当前文件夹里每个项目一个条形，附大小与比例。“旭日图”：当前文件夹在中心，每深一层就是外面一圈；点中心回上一级。“树状图”：文件夹卡片附磁盘占用大小与占父文件夹的比例；点加号展开分支，点“其余文件夹”加载更多，可切换左右或上下方向、按 Ctrl＋滚轮缩放并用滚动条移动。双击文件夹聚焦，点“上一级”返回；四种图始终显示同一个文件夹，FileTree 会记住选中的图表和树状图方向 |
| 最大的文件 | 最大的 1,000 个文件；在筛选框输入文字可以缩小列表，双击可以在文件夹树中找到那个文件 |
| 搜索 | 名称含有输入文字的文件和文件夹；模式（`*.mp4`）要匹配完整名称，多个模式用 `;` 分开（`*.iso;*.zip`）；搜索框下方的条件可以缩小范围，也可以单独使用：大于或小于某个大小、最近一周／一个月／一年内改过或超过一、二、五年没动、文件类型、只有文件或只有文件夹；搜索可以取名保存，之后再选回来；列出最大的 1,000 个匹配项目，并显示全部的数量和总大小 |
| 清理 → 建议 | 内置规则须符合文件年龄与路径／项目依据，提示会说明风险与重建方式。不确定组须手动审查，默认不勾选；较低风险缓存可整批送审，包存储库不列入。“选项 → 清理策略”控制规则、文件年龄及独立的排除项 |
| 清理 → 重复文件 | 用开头／完整哈希找出相同大小的文件（硬链接只算一份），默认最低 1 MB。每组明确选择保留副本，核对路径与估计，再选中已核对的多余副本供 Delete。已更改、受保护、未验证及硬链接组保持原样 |
| 文件类型 | 每种扩展名占用的空间；在表格上方选一种类型就只显示那一类，双击一行会列出那种文件里最大的几个 |
| 文件新旧 | 按最后修改时间（一个月内……超过 2 年）统计占用的空间；双击一行会列出那一段里最大的文件 |
| 无法读取 | FileTree 没有权限读取的文件夹；里面的内容不会算进去 |

### 释放空间

在任何项目上点右键，可以打开它、在文件管理器中显示、复制路径、在图表中显示、在 FileTree 以外改过东西之后重新扫描这个文件夹（其余结果不变）、只扫描这个文件夹，或移到回收站（macOS 与 Linux 是“废纸篓”）。要一次移走好几个项目，在文件夹树、“最大的文件”或“搜索”列表里用 Ctrl+单击或 Shift+单击选中，只会询问一次，并列出它们和总大小。FileTree 移动任何东西之前都会先询问，而且不会永久删除。系统与程序的文件夹（Windows 文件夹、Program Files、AppData 里的程序设置、用户的个人文件夹，以及 macOS 与 Linux 上对应的位置）会说明原因并多问一次；临时文件夹与缓存不会，因为那正是要清理的东西。

移动每个项目前会核对扫描记录的文件身份、类型、大小、时间、当前父路径、解析后的保护状态与文件夹内容。已更改、不存在或扫描不完整的项目会跳过并说明原因；移动、跳过与失败分别计数。“停止”可取消剩余项目；完成后会重新扫描受影响的父文件夹。状态栏显示移动容量，清空回收站后才增加可用空间。记录文件身份会增加扫描时间与内存，Windows 尤其明显。

移动失败时，后台诊断会列出观察到打开文件的程序及 PID（Windows Restart Manager 或 Linux `/proc`），不会自动关闭程序。文件夹诊断最多查询 256 个已扫描文件；无法访问的进程、目录句柄及其他失败原因可能未知，观察到占用程序也不能证明它就是失败原因。

点击“选中这一组”或“全部选中”会在确认移动前打开审查队列，逐项显示路径、规则、原因、日期、逻辑与分配大小、保护状态及删除后果；表格下方会显示所选项目的完整说明。可以取消勾选以保留项目，或打开所在文件夹。父项目与子项目重复选择时只保留最外层。后台估计会把硬链接的共享分配空间只算一次，仍有其他名称的文件不列为可回收数据。清空回收站后可回收的文件数据以保守范围呈现，共享区块及文件夹元数据仍未知。

“**文件 → 最近操作**”显示最近 500 个已确认的操作，包含移动、跳过与失败。日志只记录时间、原始路径、磁盘／文件标识、理由、结果，以及 Qt 提供的回收站位置，从不保存文件内容。仅追加的 JSONL 分段以原子方式写入应用程序本地数据目录的 `journal/`，保留 90 天／50 MB。先记录确认才执行操作；无法记录时跳过移动。结果写入失败时会尽可能停止剩余移动，并提示记录可能不完整。中断后只有确认记录的操作，其最终结果未知。CSV 导出会将主目录前缀替换成 `{HOME}`；记录回收站位置不保证可还原。保留管理只移除 FileTree 自有的日志分段，不会移除扫描的文件。

规则会说明分类、依据、最低文件年龄、风险与重建方式。近期或无日期项目不列入，文件夹按最新的子项计算（缓存／构建／临时／空文件夹 7 天、包下载／崩溃转储 30 天、安装文件 90 天）。浏览器个人设置、包存储库（`.m2/repository`、`.nuget/packages`、`.gradle/caches`）及仅名称像缓存／构建的文件夹不列入。项目输出须有项目描述文件，Python 缓存须有生成文件的依据。临时文件、崩溃证据、下载、构建输出及空文件夹使用“手动审查”，默认不勾选且不包含在“全部选中”中。较低风险的缓存仍须审查与确认。

“**选项 → 清理策略**”可启用／停用每条规则、设置最低文件年龄，或排除绝对路径／名称模式（每行一个）。排除子项也会避免把其父文件夹整个列入。这与“扫描时跳过”独立：不提出清理建议的数据仍计入磁盘用量。未修改时保留内置规则。保存前会根据当前扫描预览增加／移除的候选数量与逻辑容量，修改设置会使预览失效。策略保存在 QSettings，仅接受经验证的第 1 版 JSON 导入（支持的规则、布尔开关、0–36500 天与排除项）。已保存的设置无效时会停用建议，直到重新审查；手动审查风险不能调低，也不支持自行执行的规则。

### 看看哪里变大了

“**文件 → 扫描历史…**”显示此根目录保留的容量折线图及最多 1,000 条扫描。选中先前扫描即可打开已有的“变化”选项卡，不必选择文件；Ctrl+C 可复制行。历史默认启用，**所有根目录合计上限 1 GiB**。“**选项 → 扫描历史设置…**”可停止未来保存或调整上限（1–16384 MiB），降低上限会在下次保存时应用；关闭后仍可读取已有历史。整个扫描将文件夹路径、名称、容量与覆盖范围，以兼容的扫描 JSON 存入应用本地数据目录的 `history/<root-path-hash>/`，不含文件内容。停止的扫描及局部重扫不保存；含读取错误的完成扫描标记为不完整，缺少文件夹不代表已删除。按名称计算的分配量分别计入硬链接名称，比较描述元数据而非验证内容。只从所有根目录按时间移除识别为历史的元数据，以符合上限；拒绝链接目录、链接文件及其他数据。单条快照超过上限时会跳过并显示错误，扫描仍可完成。保存／读取失败会显示；停止或关闭会等待后台读取结束。历史仅存本地，不计划扫描，也不移除记录中的源文件。

用“**文件 → 导出 → 文件夹树（JSON）**”把扫描保存起来。之后重新扫描，选“**文件 → 与之前保存的扫描比较…**”打开那个文件，就会出现“**变化**”选项卡，列出每个有变化的文件夹之前和现在的大小，变大最多的排在最前面；新的文件夹标示“新增”，消失的标示“已不存在”。在点“结束比较”之前，之后的重新扫描都会继续比较。文件夹是按它在扫描文件夹下面的路径对应，所以也可以拿来跟放在别处的同一份数据（例如备份）比较。

### 小知识

- 大小是文件的实际大小，按二进制单位计算（1 KB = 1,024 字节），和 Windows 资源管理器相同；可以在“视图 → 大小单位”改用固定的单位。
- 在 Windows 上，FileTree 启动时会像 TreeSize 一样请求管理员权限，受保护的文件夹也能读取。拒绝的话它照常以普通权限运行，读不到的文件夹列在“无法读取”标签页，那里有“以管理员身份重新启动”按钮（“文件”菜单里也有）。不想每次被问，可以关掉“视图 → 启动时请求管理员权限”。
- “最大的文件”、“文件类型”与“文件新旧”默认统计整个扫描范围；点这几个选项卡右上角的“只看选中的文件夹”，就会改为跟着文件夹树中选中的文件夹。
- 默认会计算隐藏文件；关掉“视图 → 包含隐藏文件”，下次扫描就不会算进去。
- 清理建议会显示已知容量，以及跳过、无法读取、尚未扫描的文件夹数；省略部分的容量为未知。不完整的分支不会被整体建议清理，也不会被视为空文件夹。扫描不完整时禁用“全部选择”；清理前请重新扫描相关分支。刷新时会清除过期建议。
- 要让某些文件夹每次都不扫描，把它们加进“视图 → 扫描时跳过”：像 `node_modules` 或 `*.cache` 这样的名称会跳过所有同名的文件夹，路径只跳过那一个文件夹。跳过的文件夹会以灰字列出，大小为 0。
- 语言、大小单位、窗口布局与最近扫描过的文件夹都会记住（Windows 上保存在注册表的 `HKEY_CURRENT_USER\Software\JE-Chen\FileTree`）。

重复文件的总量标为“逻辑大小”。每组请选择文件行并按“保留选中的副本”，列表会标明保留副本的完整路径，并保留名称、日期与父文件夹供比较。估计按这些选择显示不重复分配空间及清空回收站后可回收数据的保守范围，未决定的组保持未知。“选中多余的副本”只包含范围、保护状态、更改与硬链接名称（含扫描范围外的名称）核对成功的组。确认后会重新完整哈希并核对该组所有文件；核对失败时整组保持原样并要求重新扫描。“停止”取消剩余工作。系统移动失败仍可能造成部分批次完成；回收站移动不是整组原子操作。压缩／稀疏文件按分配大小计算，哈希不打开已知的云端占位文件。共享区块及文件夹元数据仍未知，移到回收站本身不释放空间。隔离磁盘实测仍待完成。

相同文件夹会列在文件组上方，以“副本 = 原始文件夹”显示，沿用搜索所得的哈希，不会再读取内容。每个非空文件都须有已验证哈希，且相对名称、大小、哈希与空文件夹结构须相同。未哈希的小文件／独有文件、链接及不完整分支会阻止文件夹配对。已包含在父配对中的子项不重复列出，其他位置的额外副本仍会列出。这些行仅比较搜索快照，不代表可移除文件夹。

### 容量明细

Windows 的“**文件 → 已安装程序…**”列出最多 1,000 个卸载注册项及识别到的 Steam／Epic 游戏名称，并显示完整数量及元数据失败情况。只读查询 HKLM／HKCU 的 32／64 位视图，不修改注册表。`EstimatedSize` 是报告的 KiB 估计；文件夹逻辑／分配量只取自当前扫描中完全匹配且不是链接的文件夹。缺少位置及无法读取／跳过范围保持未知或不完整。Steam 清单取自扫描中的 `steamapps`，也会读取 Epic 固定的 `%PROGRAMDATA%/Epic/EpicGamesLauncher/Data/Manifests`，可核对另一磁盘的游戏名称。每份清单限 1 MiB，核对扫描及打开文件的快照，跳过已知云端／链接状态，并报告格式错误或变化。共享／嵌套安装文件夹可能重叠，请勿合计行或推算卸载可释放空间；部分打包／便携式应用不会列出。双击选中匹配的树状文件夹，Ctrl+C 复制行。按钮以固定 URI 打开 Windows 已安装应用设置，不执行注册项的卸载命令。停止或关闭会等待后台工作结束并忽略取消的回复。此视图仅限 Windows。

账本也会识别绝对路径的自定义 `XDG_DATA_HOME/Trash`；相对路径设置会使用默认数据目录。

文件夹树上方会显示系统已用／可用空间，以及硬链接只算一次的文件分配估计。“容量明细”会区分按名称计算的分配、硬链接重复量、已读取的回收站数据（已包含）、跳过／无法读取的范围及其他挂载磁盘。完整扫描整个磁盘时，会把无法解释的差额列为“无法归账”。仅扫描文件夹、扫描不完整、缺少标识信息或分配估计超过系统已用空间时，都无法核对整个磁盘。文件系统元数据／保留空间、跳过的字节及其他磁盘的总量保持“未知”，而非 0。系统容量與文件快照不是同时测量，共享区块、快照与 Windows 分配估计会影响差额；自建 ext4 容量／保留空间及硬链接／稀疏文件回收案例已通过 CI；NTFS／APFS 与共享区块仍待验证，因此账本只称为估计。Linux 回收站的逻辑内容量，与账本含内容及收据的分配量范围不同，均不是额外计入的容量。命令行的扫描记录也会在 `capacity` 字段包含这些数字。跨磁盘的文件夹挂载点只列出、不继续扫描。Linux 也会在遍历前及返回结果前读取 `/proc/self/mountinfo`，跳过明确的文件夹挂载点，包含同设备 bind mount 及经祖先别名到达的路径。挂载边界列在“无法读取”，跳过字节保持未知；直接选择挂载文件夹作为扫描根目录仍可扫描。挂载表丢失或格式错误时，会在遍历前停止。其他 POSIX 系统仍采用设备边界检测。Linux 会在读取条目元数据期间保持文件夹描述符打开，检查挂载 ID 与原有标识信息；相关挂载点或根目录挂载变化时，拒绝返回成功结果，请按错误提示重新扫描。失败扫描不写入历史；所选范围以外的挂载变化不会中止扫描。Linux 需要可读取且含挂载 ID 的 proc 元数据（内核 3.15 以上）。内核 5.8 以上且 libc 支持时，使用经结果标志确认的 statx 描述符查询，避免每个文件夹额外打开与解析 proc 文件；不支持、拒绝或缺少结果时改读 fdinfo。这仍不是文件系统事务快照。私有 Linux 命名空间的自建静态同设备 bind mount 已通过 CI；CI 也测试打开文件夹前后的实时 bind mount，并记录描述符防护的耗时。

在文件夹树的列标题单击右键，可选择显示的列，设置会保留。名称列保持显示并默认为可读宽度，额外列可水平滚动。“**占磁盘比例**”可选择显示，与“占上级比例”并列，按逻辑字节除以系统报告的磁盘总容量。容量尚未获取、文件夹树变更后及其他磁盘项目会显示未知；硬链接名称仍分别计算，因此不是分配或可回收空间。

## 不开窗口的命令行

命令行入口只使用核心，不会加载 Qt。CSV／JSON 导出与窗口相同，以原子方式写入；比较会列出绝对变化最大的项目，最多 `--limit` 项（默认 1,000）。标准输出是逐行 JSON，使用固定字段（`file-tree-cli/1`）并包含扫描覆盖范围；比较会增加 `changes` 记录。错误以 JSON 写到 stderr。默认两个工作线程，可用 `--workers`、可重复的 `--exclude` 模式及 `--no-hidden` 控制扫描。

```bash
je-file-tree-cli scan D:\ --folders folders.csv --largest largest.csv --json tree.json
je-file-tree-cli scan D:\ --compare old.json --limit 20
python -m je_file_tree.cli scan D:\ --exclude node_modules --workers 2
```

退出代码：**0** 覆盖范围完整、**1** 不完整（包含排除及无法读取的项目）、**2** 参数错误、**3** 扫描／比较／导出 I/O 错误或保存的扫描格式无效、**130** 已中断。Ctrl+C 会停止扫描并导出已读取的部分；再次按 Ctrl+C 则立即中止。每份导出独立完成原子写入，后续导出失败不会撤销先前完成的报告。命令行不提供删除或自动清理。

```bash
pip install -r dev_requirements.txt
python -m pytest
python -m ruff check .
python tools/make_screenshots.py
```

`tools/make_screenshots.py` 会用一个虚构的文件夹重新绘制 README 里每种语言的图片。代码结构、主要流程与设计规则写在 [architecture.md](../architecture.md)。

整盘扫描可以设置资源预算后测量（默认两个工作线程、512 MB、180 秒）。因预算而停止的扫描会在报告标为不完整；重复文件哈希另有时间限制。CSV 与 JSON 导出以流式写入临时文件，再替换目标文件，大型扫描也不必在内存保留另一份导出数据。

python tools/measure_scale.py C:\ --gui --memory-mb 768 --duplicates-seconds 10 --output scale.json
