# FileTree

关闭或取消分析／文件操作窗口时，会先请求取消，再于后台任务安全结束后异步完成关闭。原生调用尚未结束时，窗口仍保留任务并阻止其他源文件操作；重复关闭会保留第一次决定。实际的部分结果与错误会在关闭前显示。切换预览会等待已取消的读取结束，只启动最后一次请求；已取消且尚未启动的操作不会执行。Qt 控件与模型仍由主线程处理。整个应用程序退出时仍会等任务结束再释放对象。

来源操作与分支重新扫描也会异步等待已取消的后台读取。回收、撤销及已批准的清空回收站操作，会等所属读取任务结束才启动；结果也会等操作任务结束才解除其他操作的限制。停止会取消排队中的回收、撤销或分支请求，不调用其原生操作。

切换变更监视时，旧读取任务会异步结束，完成后只启动最后一次请求的监视器。历史记录／比较结果、定期审核交接及虚拟磁盘查询的完成处理，也会异步等任务结束后才开放下一步操作。

拖放协商只使用已复制的本地路径引用，不查询文件系统。后台任务会验证第一个实际拖入的文件夹与明确选择的多文件夹；连续拖放会合并，新扫描会使待处理的拖放失效。多文件夹验证会预留有上限的名额、保留选择顺序，取消时等查询安全结束再异步关闭。后台容量／扫描的完成处理也使用异步结束通知。

文件夹验证与欢迎页的磁盘查询由后台任务执行；界面与操作状态使用已复制的磁盘数据。切换扫描会请求取消，异步等待旧扫描、原生变更监视与低负载扫描安全结束，再启动最后一次请求。连续切换会合并请求；停止会丢弃尚未启动的新扫描。耗时的原生调用仍保留任务对象直到结束，期间 GUI 事件循环持续处理事件。这些变更不代表扫描速度提升。

**看看磁盘空间都用到哪里去了。** FileTree 会扫描一个文件夹或整个磁盘，把里面每个文件的大小加总，先列出最大的文件夹和文件——用文件夹树、彩色的方块图和最大文件列表呈现。找到不需要的东西时，直接在窗口里把它移到回收站。

**选项 → 跟随变更** 默认关闭，每个结果选项卡可独立跟随完整、实际的 Windows／Linux 扫描。后台原生 USN／目录通知／inotify 将数量受限的变化合并一秒，只重扫已记录的受影响文件夹，其他待更新分支保留在队列。扫描、分析、来源操作审核、询问窗口及有效撤销提示期间延后更新。事件丢失、未知范围、硬链接计数及来源操作间隔须完整重扫，每五分钟再完整核对，涵盖设置／重新启用的观察间隔。不完整、合并或不支持的范围不能启用；原生错误持续显示，不自动重试。Windows 部分范围含共享文件时须可读取 USN，才能涵盖范围外别名。关闭选项或选项卡会取消并等待监看任务结束。通知不授予来源操作权限。独立 Python API 为 `change_watch.watch`；原生 CI 已验证 Windows USN 与 Linux inotify，包含 Windows／Linux 范围外别名写入。

**选项 → 后台监视器…** 默认关闭。启用后，关闭窗口会将 FileTree 保留在托盘；**退出** 一定等待全部任务并结束。没有托盘时窗口保持显示，托盘消失也会恢复隐藏窗口。后台任务每分钟读取系统可用容量，低于阈值时（默认 10%）通过支持的系统通知与状态／提示显示；系统偏好设置可能停用通知，未知容量保持未知。可选最多 32 个文件夹及 1–720 小时间隔，以单个低优先级线程扫描并保存至已启用的本地历史。扫描不改动结果选项卡或来源，不完整范围保持明确。跨进程持久记录防止重复尝试；失败／取消的期间不重跑，错过多次计划只合并一次。前台扫描／来源审核会取消并等待低优先级任务。停用也等待任务并恢复窗口。`py -3 start_file_tree.py --background` 不询问提升权限，仅在监视已启用且托盘可用时隐藏；标志不会启用监视。不自动清理。核心 API `background.MonitorConfig`、`claim_scan`、`due_roots` 及 `SpaceWarnings` 保持独立。

同一对话框中的 **登录时启动此监视器** 需另外选择启用，显示实际原生注册状态与位置：Windows 当前用户的固定 HKCU Run 值、Linux `$XDG_CONFIG_HOME/autostart/je-file-tree-background.desktop`（默认 `~/.config`），或 macOS `~/Library/LaunchAgents/io.github.jechen.FileTree.background.plist`。取消勾选并接受会移除拥有的项目；停用监视也会清除此选项。适用下次登录，不启动第二个程序或结束当前会话。外来／已更改项目、链接的 POSIX 目录／文件与共享元数据会拒绝并显示错误；使用固定绝对路径参数，不使用 shell。移动程序前，请先移除旧登录项目，再在新位置注册。Windows 命令超过 260 个 UTF-16 字符、Linux 路径包含百分号（或执行文件路径包含等号）会拒绝。系统启动策略可能抑制启动；原生测试数据验证不证明实际登录启动。

原生 CI 会保留后台／历史／容量测试来源的阶段 JSON 与 CJK 截图。隔离的 Linux X11 桌面要求实际托盘与可见通知截图；Windows／macOS 明确记录托盘可用或不可用的行为。仅调用通知不证明系统显示权限。这些验证不注册主机登录任务，也不改动既有用户来源。定期建议审查验证使用原生平台上的 Qt 对话框，实际按下“否”，完成后还原进程对话框设置；OS 原生提示框交互仍未验证。已核对的 cocoa 重跑完成八次自有 Qt 审查／否确认及两次 APFS 清理：[原生 Qt 验证](../docs/updates/background-20261009-native-widget.json)。

独立 Python API `recurring.capture`／`prepare` 结合已记录的扫描元数据、有效清理策略及相符的历史记录，描述新增候选项目与最大的文件夹增长。历史观察最多 100 行／48 KiB；缺少、部分、不相符或截短的基准保持未知。元数据上限会预留历史保存时间戳；无法容纳的头部会明确拒绝。`ScanHistory.save(..., baseline=...)` 将可选观察存入一般保留上限内，`load_recurring` 检查历史关联。只有文件读取错误时，也会标示历史不完整。带日期的建议在下次计划到期时失效，规则、记录或扫描路径改变也会拒绝。这些 API 不扫描或移动来源。

“文件 → 计划扫描建议”显示低负载计划任务生成的报告：相较上次相符扫描新增的垃圾候选、当前候选，以及逻辑容量增长最多的文件夹。每份列表最多 100 行，提供完整路径提示及 Ctrl+C 复制。日期、到期时间、候选总数／显示数、覆盖范围与未知比较均明确显示；规则、计划或扫描记录更改会更新状态。报告在本次运行的计划扫描后出现，基准数据按本地历史保留设置保存。建议元数据无效时，仍保留普通扫描历史并显示错误。不会自动移动来源。“重新扫描并审核当前候选”会在新标签页执行普通前台扫描，由工作线程验证完整扫描与实际源，再进入既有可编辑清理队列、受保护文件夹及回收站确认流程。已更改、不完整或到期的建议无法继续。取消重新扫描或关闭其标签页会放弃审核请求。移动任务会在整批开始前重新验证完整源，并于每个项目之前检查日期、规则、计划及扫描记录；普通原生源验证仍照常执行。这些检查是观察结果，不是文件系统事务。

在树形列表、搜索或最大文件列表选中实际项目，右键 → **移动到文件夹…** 或 **重命名…**。预览窗口列出每个最外层源／目标及拒绝原因，最多选中 1,000 个项目。选择现有文件夹，或使用字面 `{name}`、`{stem}`、`{ext}`、`{n}` 替换的文件名模式。名称已存在时默认 **跳过**；明确选择编号后缀可预览实际替代名称。改变选项后确认失效，请重新点击 **预览路径**。**应用已查看的路径…** 显示默认为“否”的纯文本询问，详细信息列出每组可执行路径；拒绝／未变化的行仍显示并跳过。执行时固定选项，重新检查完整源记录与上级标识，以原生同磁盘不覆盖重命名操作，不复制或覆盖。拒绝受保护、链接、特殊、已知不可用、已变化或跨磁盘项目。停止／关闭须等待当前重命名完成，保留已完成的变化。逐项错误及实际路径保持可见；操作后记录不符时尝试不覆盖地恢复，失败则报告保留的目标。并发文件系统变化不具事务保证。范围外的目标上级在专属后台任务重扫，显示数量／错误；关闭后重建当前根目录，更新范围内两侧上级，并清除旧容量元数据。取消重扫的结果仍可见。Python API 提供 `namespace_moves.prepare_namespace`／`execute_namespace`、已移动／跳过／失败结果及两侧上级路径。macOS 原生行为仍未验证；跨磁盘请使用独立的 **移动到另一个磁盘…** 验证复制流程。

在文件夹树、搜索或最大文件列表选择已扫描的文件夹，右键 → **移动到另一个磁盘…**。选择另一个磁盘上的现有文件夹，查看每组实际路径及明确跳过／加后缀的冲突选择。**复制并验证已查看的文件夹…** 显示默认为“否”的纯文本询问并固定选项；进度列出当前文件。停止／关闭会取消并等待工作线程，保留原始数据及部分目标，显示实际路径／错误。成功复制后才能按 **将已验证的原始数据移到回收站…**，沿用受保护文件夹确认流程，另行显示默认为“否”的回收站询问，列出源／副本及 64 MiB 验证限制。回收站工作线程在每次移动原始数据前重新验证，失败即停止剩余移动。**留下 junction／符号链接** 默认关闭，整批固定；仅成功移入回收站后才在原位置创建，遇到新项目不覆盖。链接失败仍保留已验证副本及回收站内的原始数据，报告实际路径；Windows 原始路径可能留下空文件夹。复制后不自动回收原始数据。范围外目标上级在专属线程重扫；移入回收站后更新源上级，拒绝回收则重扫当前根目录。关闭主窗口会等待进行中的路径操作窗口，并显示等待回收站操作期间收到的副本验证错误。自建数据已验证 Windows 原生 C→D 复制／ADS 与 junction；macOS 原生行为仍未验证。

Python API 新增 `verified_copy.prepare_copy`／`copy_folders`／`verify_copy`，供明确审核后不覆盖地复制普通文件夹，包括跨磁盘目标。预览保留每组最外层路径／拒绝原因，提供明确跳过／加后缀选择，最多 1,000 个选中项目。可读取受保护的普通源，后续移到回收站仍须沿用受保护源确认流程。拒绝链接、特殊、已知不可用／重解析、记录不完整、已变化或挂载的内容。不覆盖现有名称；保留空文件夹，硬链接名称复制为独立副本。比较完整子项目名称、文件数与长度；每个小于 64 MiB 的主要文件／Windows 命名数据流以 SHA-256 比较，更大的内容只比较长度。Windows 原生复制保留 ADS，数据流查询失败则不能验证。POSIX 扩展属性严格复制及比较；macOS 使用原生描述符复制／资源分支比较，64 MiB 以上的属性只比较长度。文件元数据按平台支持处理；Windows 文件夹安全性继承目标，POSIX setuid／setgid／sticky 位不转移。检查目标描述符的已知文件系统边界及 Linux 同设备挂载标识。失败停止整批，保留所有源并报告部分目标；取消也保留部分数据。验证记录须在另行确认的现有回收站操作前重新核对。此 API 不回收、删除或在源创建重定向链接；观察不具并发文件系统事务保证。macOS 原生 CI 已以自建数据验证同磁盘复制、完整资源分支／扩展属性哈希及空文件夹；[自建 APFS 证据](../docs/updates/apfs-20261009-native.json) 亦验证原生跨磁盘复制、源及空文件夹保留。后续 Finder 回收／重定向仍待验证。

只读的 `duplicate_links.prepare_links`／`verify_link_pair` API 可从明确保留副本的重复分组预览最多 1,000 个额外副本替换。每行固定准确路径、扫描／句柄记录及上级标识；受保护、已变化、未知、链接、特殊、云端或已有硬链接的决策会拒绝，其他磁盘或 Linux 同设备 bind 挂载副本保留为拒绝行。验证重新核对当前树结构及每项记录，对任何大小的两份主要内容与每个 Windows ADS 完整计算 SHA-256，并核对原始重复文件 BLAKE2 哈希。POSIX 扩展属性必须相同；macOS 属性／资源分支达到 64 MiB 或总内容超过 64 MiB 时拒绝，不以只比较长度代替。取消保留所有内容。此 API 不创建硬链接、不替换／删除，也不提供后续变更权限。明确确认后调用的 `duplicate_link_ops.execute_links` API 会完整重验每个分组／配对，创建原生同磁盘硬链接，先将旧副本以不覆盖方式保留在专用同级备份名称，再发布新名称。再次完整验证内容后，只移除该记录的备份。失败会尝试不覆盖的恢复，保留新到达条目；结果显示实际已发布的别名与留下的备份／临时路径。取消停止尚未开始的任务并保留部分结果。旧副本不保留在回收站，任一名称的内容或元数据／权限变更会影响全部名称。保留与额外副本的上级都必须重新扫描；回收容量未知。原生 Windows 自建测试已验证多副本、ADS 备份移除、取消及名称冲突。下方说明确认界面流程；macOS 原生 CI 已验证一般核心硬链接、保留文件身份及完整资源分支／扩展属性哈希；受保护来源的界面确认仍待验证。

**选项 → 测量 Windows 逐文件磁盘大小** 默认关闭，应用到后续完整／分支扫描，启用后请重新扫描。此功能以不跟随链接的元数据句柄查询 `FILE_STANDARD_INFO`，核对完整的 64 位卷／128 位文件标识（Python 3.12 之前使用旧版 stat 标识）、大小与修改时间；即使未显示普通压缩标志，也能测量普通文件与 XPRESS／WOF 的分配大小。已知云端／离线文件仍不查询并记为零，不支持、权限不足或记录已变化时采用已说明的大小估计值。逐文件查询会增加扫描时间，不读取文件内容；共享数据区段与文件夹元数据仍未知，硬链接仍按各名称计算。默认扫描对普通文件保留簇估计值。原生自建测试文件通过 NTFS／XPRESS8K 压缩及解压缩内容核对，逐文件测量的重新扫描记录了 2 MiB XPRESS 文件的 73,728 字节分配大小，该文件未显示普通压缩标志。

Windows 已扫描文件夹的右键菜单提供 **NTFS 压缩…**。可取消的只读预览显示最大的 1,000 个已记录日志／文本／代码／可执行文件／可能未压缩图像候选项、全部数量及逻辑大小／具名磁盘分配。可能节省量为 **0–候选项的磁盘分配**，不保证压缩率或可释放空间。可选 NTFS、XPRESS8K（很少修改的数据）或解压缩；解压缩会列出安全的已记录类型，不依赖压缩标志。**处理列表中的文件…** 以默认否的问题显示范围、模式、列表数量与逻辑字节。仅处理列表文件，不处理全部候选项，也不改变文件夹默认值与列表外文件。原生工具仅适用当前的本地固定 NTFS 磁盘，重新核对记录的标识，并以句柄防止所有上级文件夹与文件被重命名／删除。拒绝链接、已知云端／离线、稀疏、隐藏／系统、硬链接、受保护及已更改／未知项。不使用 shell、通配符或 `/s` 递归；解压缩会执行 `/u` 与 `/u /exe`。压缩可能降低写入速度，解压缩需要可用空间。停止／关闭会终止并等待命令；先前／当前文件可能保留部分更改。结果显示核对成功的已知前后分配、未知数量及前 20 条错误。关闭后会临时启用逐文件磁盘大小测量，重新扫描完整范围／分支；之后的手动扫描仍按选项设置。预览不读取文件内容，确认后的原生操作可以读取。操作前双击可选择记录的文件，Ctrl+C 复制列表。原生新建临时文件验证保留 SHA-256、还原分配、拒绝硬链接，且 junction 外的对照文件未变化。

**用户** 标签页按整份扫描的文件所有者累加，显示最大的 1,000 组，并保留全部分组／文件／字节数，列含逻辑大小、具名磁盘分配、文件数及逻辑大小占比。POSIX uid 使用扫描已读取的 stat；Windows 的 **选项 → 记录 Windows 文件所有者** 因逐文件安全性查询成本较高而默认关闭，启用后请重新扫描，设置应用到后续完整／分支扫描。共享不可变的 uid／SID 标识增加一个所有者字段（测量每个节点增加 8 字节）。Windows 只读查询普通文件的所有者 SID，跳过链接及云端／离线文件，查询后重新核对记录的元数据。未启用、无权限、缺少或已变化的所有者独立列为 **所有者未知**，扫描不完整也会标示未读取数据。打开标签页才会在可取消的后台任务累加并查询账户名称，名称无法解析时保留 uid／SID。停止、切换标签页、新扫描及关闭会丢弃已取消响应，关闭等待所有任务结束；移动及分支重新扫描会使总计失效。**刷新记录总计** 仅重新汇总扫描，所有者已变化时请重新扫描。支持 Ctrl+C 与当前列表 CSV 导出。文件夹所有者不会应用到其中的文件，硬链接仍按各名称计算，磁盘分配仍为估计值。所有者不能证明实际使用或移除权限，此标签页不会生成清理操作。仅含文件夹的 JSON／历史记录不保存文件所有者。

**选项 → 记录文件访问／创建时间** 默认关闭，适用于之后的完整与分支扫描；开启后请重新扫描。沿用已读取的 stat，每个普通文件快照增加 16 bytes，不新增 Node 字段或额外时间查询。文件夹树标题菜单提供默认隐藏的“记录的访问时间”与“创建时间”列。**文件 → 文件时间…** 可按记录的访问／创建时间，筛选至少多少天前的文件（0–36,500 天，默认 730）；显示最大的 1,000 个符合条目，以及全部符合数量、字节与未知数量，支持 Ctrl+C、选中树中对应条目、停止与关闭后等待后台任务结束。整棵树的筛选在工作线程进行。缺少或在未来的时间保持未知；不记录文件夹与链接时间。创建时间取 birthtime（旧版 Windows Python 缺少 birthtime 时才用 ctime），不使用 POSIX ctime。只读查询 NTFS `NtfsDisableLastAccessUpdate`，包含初始化与系统管理标志；报告停用或配置未知时，无法按访问时间筛选，仍可按创建时间筛选。注册表值可能需重启，且无法证明每个磁盘实际采用的配置。其他文件系统／提供者也可能延迟或停用 atime，后台读取也会改变日期，记录时间无法证明实际使用时间。此视图不会准备清理操作。最大文件 CSV 新增 `accessed`／`created` ISO 日期，未知时留空；仅含文件夹的 JSON／历史不保存文件时间。

扫描栏的“**暂停／继续**”会暂停获取新文件夹。当前文件夹读取会完成，文件夹树仍持续更新；暂停时仍可“停止”或关闭窗口。最后的结果分析不能暂停。经过时间包含暂停期间，继续时保留同一份扫描及计数。

“**选项 → 低优先级扫描**”默认关闭，应用到新扫描。每个扫描线程使用 Windows 后台 CPU／I/O 模式，或 Linux nice 10 与最低的 best-effort I/O 优先级，不影响界面线程。不支持的平台、权限拒绝或仅部分应用会报告；可读文件夹仍继续扫描。I/O 效果取决于磁盘调度器，扫描可能花费较长时间。命令行及测量工具接受 `--gentle`，命令行 JSON 包含 `warnings`。

矩形树图与旭日图共用“**颜色 → 按修改年龄**”，使用“年龄”列表的范围，并显示由浅（近期）到深（较旧）的图例。颜色按扫描／分析时间计算，鼠标移动时不会随时钟改变。文件夹按最新修改记录着色；无可用日期、未来日期与合并的小项目为灰色。这表示修改年龄，不能判断最后访问时间或是否未使用。

“**文件 → 导出**”与图表右键菜单可将屏幕上的图表保存为 **PNG**，包含当前可见范围、配色及选择状态。条形图与旭日图另提供 **SVG**：有数量上限的完整条形行或圆弧会绘制成矢量图形与文字，不使用旭日图的缓存位图。PNG 编码与文件写入由导出线程处理，以原子方式替换文件；关闭窗口会等待导出完成。

“**文件 → 打印当前视图**”（`Ctrl+P`）会打开系统打印对话框。“**文件 → 导出 → 当前视图（PDF）**”会保存一页 A4，按捕获的视图选择横向／纵向。两者将当前标签页及可见范围等结果等比例放入可打印边界，不拉伸或裁剪；输出是捕获的像素，滚动范围外的项目不在其中。PDF 由导出线程使用 Qt PDF 引擎写入，以原子方式替换指定文件；关闭窗口会等待完成。

图表页提供可点击的文件夹路径与 **返回／前进**（`Alt+Left`／`Alt+Right`）。历史保留当前扫描最近 100 次浏览；返回后打开其他文件夹会替换前进历史。新扫描会重置历史，重新扫描会移除失效条目。长路径可水平滚动，**…** 可选择更上级的文件夹。

展开文件夹树下的 **详细信息**，可查看选中条目的大小、磁盘大小、文件与文件夹数、已记录的修改日期，以及小型类型与文件年龄分布。面板会记住展开状态；扫描结束且面板展开时才在可取消的后台任务中计算分布，仅使用已读取条目，未知与未来日期单独列出。更换选中条目会丢弃过期结果，关闭窗口会等待任务结束。

**文件 → 导出 → 当前列表（CSV）** 可保存搜索、重复文件、变更、文件类型、文件新旧、最大的文件、清理建议或问题列表，保留显示的标签、单位、筛选与排序。分组列表包含组标题及其条目，即使已折叠也是如此。列表或文件夹树获得焦点时，**Ctrl+C** 会将选中行与列名复制成带引号的制表符分隔文本；文本框仍正常复制。看似公式的文本会加上电子表格保护前缀。CSV 获取会以短批次让出界面，通过有上限的队列交给后台任务原子写入；列表变更会取消导出并保留已有目标文件。

在 **文件类型** 双击扩展名，即可同时查看最大的匹配文件与最多 1,000 个 **所在文件夹**，包含匹配类型的大小、文件数及占全部匹配字节的比例。文件夹仅统计直接包含的文件，嵌套文件夹不会重复计算。两份列表在可取消的后台任务中一起计算，并遵循 **仅选中的文件夹** 范围。变更扩展名、扫描或范围会丢弃旧结果；**显示全部** 可返回普通列表。按文件年龄查看文件也在后台运行。

Windows 的 **详细信息** 会解释休眠、分页与交换文件、Windows.old、回收站、System Volume Information、WinSxS、Windows 更新下载及传递优化缓存。识别使用磁盘根目录或当前 Windows 安装的完整位置，包含其子条目，不会仅凭同名判断。按钮打开对应的 Windows 设置或系统工具；FileTree 不执行清理命令，也不移动这些系统管理条目。操作后台任务也会拒绝包含它们的文件夹，并重新检查解析后的路径。WinSxS 汇总可能包含共用硬链接；未读取的系统数据仍未知。

四种图表提供辅助工具名称、键盘操作说明，以及当前文件夹与选中条目的已记录大小及数量。用 Tab 或点击将焦点移至图表：**方向键** 选择已绘制条目，**Enter** 打开选中的文件夹，**Backspace** 返回上级。树形图保留上／下选择卡片及右／左展开、折叠的操作；条形图与树形图会将选中行滚动至可见位置。导航使用有上限的图表布局，合并或未显示的条目可在文件夹树查看。Alt+Left 等组合快捷键保持原有操作。

**查看 → 主题 → 系统／浅色／深色** 可立即切换并记住选择。系统模式恢复原生平台样式与调色板；指定主题使用一致的 Qt 控件，以及清晰的文字、选中与禁用颜色。调色板或样式变更会重新绘制图表。矩形树图与放射图按实际填色对比选择黑字或白字；矩形树图仅在渐变两端都维持至少 4.5:1 对比时保留渐变。条形图的名称与数值使用当前调色板，显示在彩色条形之外。


新增的核心 API `multi_scan.scan_roots(paths, ...)` 可将最多 256 个明确来源放在同一虚拟根节点下扫描。重复／重叠的一般路径会合并，另选的挂载范围保持独立。各子节点保留实际绝对来源路径，虚拟根的 `Node.path` 为 `None`，不提供文件操作或 OS 容量权限。失败／待扫描来源保留不完整覆盖范围；取消会等待当前扫描器并保留部分数据。可选的硬链接计数只对全部观察范围执行一次。JSON 明确标记虚拟根，保存比较保留其身份，CSV／报告的根路径留空。历史记录需使用各实际来源根。使用“文件 → 扫描多个文件夹…”捕获文件夹列表，或在欢迎页按“扫描所有磁盘”捕获当前就绪的磁盘。合并结果支持图表、搜索、比较及导出；更改来源的操作禁用。重新扫描沿用捕获的来源列表，历史记录分别保存各实际来源。CLI `scan ROOT --also ROOT` 可重复指定 `--also`；扫描记录的 `root: null`、`roots` 为实际来源，合并 OS 容量保持未知。单一来源扫描保持原有行为。

只读虚拟磁盘发现会将 Windows `\\?\UNC\server\share` 注册与对应的普通 `\\server\share` 扫描路径合并，也支持扩展驱动器路径。保留原始捕获路径及来源证明。卷 GUID／设备前缀保持明确；此比较不提供文件操作权限，也不代表已验证实际 UNC 连接或分配行为。

**选项 → 每天检查更新** 默认开启。普通 GUI 启动 30 秒后，由后台任务仅向 `https://pypi.org/pypi/je_file_tree/json` 通过验证 HTTPS 查询版本数据；这是 FileTree 首次自动网络调用。不发送扫描路径或文件内容。较新的正式版本会在状态栏显示非模态 PyPI 链接；不会自动下载或安装更新。关闭选项即可停止调度并丢弃待处理回复。跨进程先保存查询时间，包含失败在内，每经过 24 小时最多尝试一次。CLI、Python 扫描及单纯创建窗口不启动查询。响应限制为 2 MiB、拒绝重定向，网络读取设有超时，关闭会等待当前请求结束。离线失败保留诊断状态，不中断扫描。

应用程序使用独立的**扫描标签页**。按“新建扫描标签页”或 `Ctrl+T` 扫描另一磁盘／文件夹，用 `Ctrl+W` 关闭当前标签页（关闭最后一页会退出程序）。最多 16 个标签页可同时扫描，各自持有树状数据、结果视图、筛选、工作线程及历史捕获。关闭一页会等待该页的工作；退出程序会等待所有标签页。语言切换应用到全部标签页。来源操作审核、回收、还原、复制、重命名、硬链接替换、压缩及虚拟磁盘压缩共用跨标签页的忙碌检查；各来源仍需分别重新验证快照和批准。合并来源仍为单一只读标签页。扫描并发数和温和优先级分别应用到每页，同时扫描多页时可降低工作数或启用温和扫描。Python 集成的 `create_window` 仍创建单一窗口；GUI 入口使用 `create_workspace`。

## 功能

首页以可滚动的布局整理文件夹／磁盘扫描、磁盘工具和最近扫描。路径工具栏增加明确的 **扫描路径** 按钮；Enter 使用相同的启用条件，空白输入不会开始扫描。结果页用四张统计卡片显示逻辑大小、记录的磁盘分配、文件数和文件夹数，明确区分扫描中、已完成和不完整，并可直接查看无法读取的项目。分配可能是估计值或共享空间，不代表可回收空间；扫描完成后仍然适用排除规则和挂载边界。宽窗口使用侧边导航选择分析，窄窗口改用下拉菜单；键盘导航和现有菜单快捷键会选中相同视图。分析上方仍可选择仅显示所选文件夹的列表。扫描时，即使尚未收到新的后台回复，经过时间仍持续更新；暂停会停止活动动画，停止则说明可能需要等待当前文件系统调用完成，再显示部分结果。完整的当前路径保留在工具提示中。新增文字支持五种语言、大小单位和系统／浅色／深色主题。重新打开会恢复已保存的树状列表／分析分割比例；首次显示的默认比例不会覆盖它，两侧都保持不可折叠。参见 [UI 和 UX 设计](../docs/ui-ux.md)。

**选项 → 扫描线程数…** 设置新扫描与分支重新扫描的并行数，范围 1–32；现有默认值仍最多为 4（按 CPU 数量限制），保存值无效时采用默认值。进行中的扫描保留原线程数。慢速共享可能受益于较高并行数，但磁盘／服务器在过高负载下也可能变慢，请按环境选择。Windows 可粘贴 `\\server\share` 等绝对 UNC 路径，以当前账户权限访问。权限不足／断线的分支保持不完整，欢迎页包含此提示。原生一次性 SMB 回环测试以 1／4 线程扫描 UNC 及临时映射驱动器，树状结果与本机一致，共享根目录分配单位也相符。权限不足及扫描途中断线保持不完整覆盖，没有空文件夹清理建议；测试 ACL 完整还原、源标识与内容保留均通过。这不代表慢速远程连接吞吐量，该测量仍待完成。证据：[原生 SMB 验证](../docs/updates/share-20261009-native.json)。

欢迎页、清理页或视图菜单的 **回收站…** 可检查各磁盘总量。Windows 可选中一个本地磁盘，再点 **清空选中磁盘的回收站…**。两次询问均列出磁盘、报告大小与项数，并说明永久移除。后台任务重新查询总量，拒绝总量已变化或记录不完整的回收站，再针对明确磁盘调用 `SHEmptyRecycleBinW`。这项永久移除例外仅限当前用户的系统回收站，不接受任意路径或所有磁盘范围。原生清空操作开始后不能取消，完成前禁用停止／关闭与项的激活。系统操作期间新增的项也可能被移除。错误可能留下部分已清空的回收站，会结合重新查询的总量显示。完成后更新容量／回收站元数据；重新扫描可更新主树。macOS 使用下述单独检查的 Finder 全局清空操作。验证不会清空真实用户的回收站。

Linux 的同一按钮会先在可取消的后台线程清点单个正式挂载磁盘上已识别的当前用户 freedesktop 回收站。两次默认为“否”的询问列出每组确切的 `files` 与 `info` 路径、内容逻辑大小、顶层项数与不可恢复性。仅接受完整、权限私有、所有者为当前 UID 且收据匹配的范围；范围文件夹链接、其他所有者、特殊项、缺少／孤立收据、挂载边界或超出清点上限都会拒绝。移除前立即重新推导范围并比较完整批准清点。相对于已打开目录的描述符执行移除，不跟随内容链接、不使用收据的原始路径，并保留系统回收站文件夹。变化的项会跳过；同时变化或权限错误可能导致仅完成一部分，已移除数量与错误会保持可见。开始清空后停止／关闭不能中断。容量／回收站列表会刷新，主窗口旧容量账本会清除，重新扫描可更新现有树。Linux 原生验证仅使用私有挂载命名空间中的全新 ext4 映像，保持范围外链接目标不变，不清空真实用户回收站。macOS 原生验证仍待完成。

macOS 必须是与主要登录用户相同的未提升权限 UID；root、已切换／未知用户或提升权限的身份都会拒绝。主目录取自账户记录，不使用 HOME 覆盖。**清空所有已挂载磁盘的 Finder 回收站…** 会检查当前用户的整个 Finder 回收站，与选中哪一行无关。可取消的专属后台任务向 Qt 获取所有已挂载根目录，拒绝无法访问、遗漏或超出上限的清点，并不跟随链接地清点当前 UID 的私有主目录 `.Trash` 与已挂载 `.Trashes/<uid>`。实体范围会去除重复，总元数据上限为 100,000 个项／128 层；失败时不允许批准。两次默认为“否”的纯文本询问列出范围、已挂载根目录、内容逻辑大小／项数与不可恢复性。后台任务重新推导完整清点并比较后，仅运行 `/usr/bin/osascript -e 'tell application "Finder" to empty the trash'`，不使用 shell 或插入路径，并等待应用程序响应。Finder 影响所有已挂载回收站，也可能移除操作期间新增的项；开始清空后不能取消。自动化权限、系统错误或仍有内容／无法访问都会保持可见，并刷新元数据；错误后 Finder 也可能仍在运行。主窗口旧容量账本会清除；重新扫描可获取最新树数据。测试使用可丢弃 POSIX 测试数据与模拟 Finder 执行，不清空真实用户回收站。由于没有 Mac，原生 macOS 权限、APFS、多磁盘与 Finder 行为仍未验证。

欢迎页在每个就绪磁盘下显示回收站大小／项数，清理页显示当前扫描所在磁盘。标示起初为 **尚未查询**；**刷新回收站大小** 会在可取消的后台任务查询只读快照（最多 256 个就绪根目录，优先查询扫描所在磁盘），移至回收站后或关闭回收站管理窗口也会刷新。缺少范围保持未查询；部分失败显示 **总计未知**、已知大小／数量与纯文本错误，不会当作空回收站。POSIX 大小为内容的逻辑字节，范围可能重叠，请勿累加。大小单位与语言会随设置刷新。新的完整扫描会丢弃未完成响应并重置清理页范围，关闭程序会等待查询结束。这些标示不会生成清理建议或更改扫描记录。

**视图 → 磁盘总览…** 或欢迎页的 **磁盘总览…** 列出最多 256 个就绪的已挂载磁盘与全部数量，包括文件系统、总量／已用容量、可用空间条、分配单位、回收站大小与项数。双击扫描根目录；Ctrl+C 复制行。可停止的后台任务更新系统数值与查询回收站，不读取内容、不修改项。可用空间可能扣除保留量／配额；重复挂载可能共用容量，不能汇总各行。Windows 簇查询失败会保持未知，不采用扫描器的估计替代值。POSIX 单位使用文件系统片段，不采用 Qt 的最佳传输块大小。Windows 回收站总量来自 `SHQueryRecycleBinW`；Linux 覆盖主目录 freedesktop 回收站与挂载根目录的用户回收站，macOS 使用个人 `.Trash`／`.Trashes`。POSIX 大小为逻辑内容字节，不含文件夹／回执元数据与共享分配；失败显示总量未知及已知大小。macOS 原生验证仍待完成。停止／关闭会等待当前系统调用与后台任务，丢弃取消后的响应。清空回收站是此只读总览之外的功能。

**文件 → 导出 → 扫描报告（HTML／Excel）** 经可停止的模态后台任务保存整份扫描记录，不受当前筛选与图表浏览位置影响。两种格式均含摘要／扫描范围、最大文件夹、最大文件、扩展名、分类与修改时间列表，标题显示已列出／全部数量。最大文件夹范围重叠；大小／数量保留原始字节与数字，磁盘分配仍是估计值，范围不完整时有标记。文件夹／文件各保留 1,000 条，扩展名限 10,000 条。HTML 内嵌整份根目录的矩形树图、条形图与旭日图 PNG 截图，图形范围有限；没有脚本、外部资源或网络请求。Excel 每份列表各用一张工作表，含冻结标题与筛选，转义公式样式文本与 XML 控制字符，每格限 32,767 字符，16 位以上整数以精确文本保存。成功原子替换前，停止／关闭保留现有目标。`openpyxl` 是安装时包含的应用依赖包；生成报告不读取原始文件内容。

**文件 → 项目与可重建数据…** 在可停止的后台任务检查已扫描数据，保留最大的 1,000 个项目与管理存储区，并显示全部数量。已知逻辑大小分成 **源文件／其他**、`.git` 与 **可重建数据**，另列已记录的磁盘分配与扫描范围。源文件／其他包含未分类数据；嵌套项目范围重叠，不能汇总各行。Git 指针文件不含外部元数据。Python／conda 环境标记与项目清单共用清理的保守识别规则，覆盖环境、`node_modules`、Rust 输出与项目内 Gradle 数据。双击在树中选中项目；Ctrl+C 复制行。**检查符合条件的可重建项** 将最多 1,000 个项送入现有回收站检查流程，遵守最短时间、扫描范围、规则设置与排除条件。已停止的扫描不提供清理建议。生成数据可能含自定义文件，需人工检查。独立环境、Maven `.m2`、全局 Gradle 缓存与 Docker 数据分开识别，不假定可丢弃；不执行缓存清除或 Docker 命令。

**文件 → Git 历史…** 用 `git rev-list --objects --all --no-object-names` 和 `git cat-file --batch-check` 检查选中的工作文件夹（或选中文件所在的文件夹），适合 `.git` 占据项目主要空间时使用。可停止、限时 120 秒的后台任务保留最大 1,000 个可达对象的标识、类型与 **解压后长度**，并显示全部数量；有界管道避免将整份历史存入内存。Ctrl+C 复制行。`git count-objects -v` 识别 gc 可能合并的松散对象，但所有引用可达的对象会保留，实际节省量仍未知。保留 Git 所有者检查；禁用可选锁定、自动维护、文件系统监视钩子与延迟下载。不修改仓库数据、不执行 gc，也不下载缺少的对象。需安装支持 `--no-lazy-fetch` 的 Git；缺少或较旧版本会报告错误。Git 名称提示可能有歧义且会更改换行，因此不列对象名称。

树状列表上方的 **筛选已展开的文件夹…** 仅在已展开的文件夹下匹配名称，不区分大小写。可取消的后台查询保留匹配项目及其上层路径，不搜索折叠的内容。清除输入框即可恢复树状列表与展开状态。从图表／列表选择被隐藏的目标会清除筛选，以显示目标。源／代理索引映射保留选择、排序、持久索引及实时更新；总量、图表与导出仍使用完整扫描。

**文件 → 比较两个文件夹…** 以温和后台任务独立扫描两个现有文件夹，显示完全匹配的相对路径、仅左／右侧有的项目、类型／大小／时间差异及两侧元数据。Unicode 与大小写完全匹配；不跟随链接，无法读取文件夹下缺少的项目仍为未知。元数据相同仍是 **尚未验证内容**。选中文件对后点击 **验证选中的内容**，可停止完整哈希验证，并以快照防止更改造成误判；更改、读取错误与已知云端占位符保持无法验证。哈希结果对应验证当时。Ctrl+C 与原子 CSV 导出涵盖显示的行（最多 10,000 行，并显示全部数量及不完整范围）。比较为只读，不提供同步操作。

**文件 → 云端与特殊文件…** 在可停止的后台任务查阅已记录元数据，显示最大的 1,000 个匹配项目及全部匹配项目的数量／总量。召回／脱机属性可能来自 OneDrive、Dropbox 或其他服务，提供者与本机内容比例未知。**完整内容大小** 是含在线内容的逻辑长度，下载后的分配仍未知。列表也识别 Windows 压缩／稀疏属性；没有属性却分配较少时，原因保持未知（可能是稀疏、压缩或驻留数据）。召回／脱机的分配 0 是扫描估计。界面显示不完整范围及无法获取的元数据，不打开／下载内容，也不增加每个扫描项目的字段；支持排序、Ctrl+C 及双击选择树状列表中的项目。

Windows 可用 `python tools/measure_streams.py <folder> --entries 10000 --repeats 5` 独立测量 NTFS 备用数据流。工具先计时扫描整个文件夹，再对有限数量的文件与文件夹查询额外元数据，输出 JSON。排除重解析点，失败保持未知，不打开数据流内容；数据流长度是逻辑字节，不是磁盘分配。2026-10-07 源码文件夹样本的 9,749 个项目均未发现备用数据流；额外查询耗时 1.694 秒，普通扫描 0.466 秒（五次中位数，含每项目两次标识检查）。这个样本不能代表整盘出现比例；普通扫描保持原有行为。

Windows 可用 **选项 → 资源管理器集成…**，在自己账户的资源管理器文件夹菜单添加或移除 **使用 FileTree 扫描**（Windows 11：**显示更多选项**）。保存前不会启用，不需要管理员权限，且不会覆盖或移除没有专属标记的注册项。移动可执行文件或源码文件夹后，请重新注册。命令使用加上引号的绝对启动路径，因此源码版本也可从资源管理器的工作目录启动。Windows 上的 FileTree 项目右键菜单也提供原生 **属性** 对话框。

- **点一下就开始**：选一个文件夹、点一下磁盘、把文件夹拖到窗口上，或粘贴路径。
- **并行、边扫边看**：同时读取多个文件夹；两个工作线程记录文件身份时，约 202 万项的 Windows 系统盘耗时 208 秒。扫描时文件夹树就会陆续出现，最大的文件夹排在最前面；点击停止会留下已经读到的部分。
- **文件夹树**：从大到小排列，每一行有它实际占用的磁盘空间、显示它占所在文件夹比例的条形，还有文件数、文件夹数与里面最近一次变动的时间。
- **图表**，四种看文件夹的方式，在选项卡角落切换（一开始是方块图）：**方块图**（每个文件一个方块，大小代表占用的空间；文件夹里小到看不见的文件合成一个斜线方块）、**条形图**（文件夹里每个项目一个条形，从大到小，附大小与比例）、**旭日图**（当前文件夹在中心，每深一层就是外面一圈）和**树状图**（可展开的文件夹分支，每张卡片附大小与比例）。单击可以在文件夹树中找到它，双击可以聚焦文件夹，四种图会一起跟着。
- **最大的文件**：整个扫描范围内最大的 1,000 个文件，附筛选框。
- **搜索**（Ctrl+F）：按名称，或 `*.mp4` 这类模式，在整个扫描范围内找文件和文件夹。
- **清理**：列出通常可以删掉的东西——临时文件、浏览器缓存、崩溃转储、包缓存、可以重新构建的构建产物、下载文件夹里的旧安装包、空文件夹——按种类分组，并说明删掉各种东西的影响。
- **重复文件**（在“清理”里）：把内容相同的文件分组，并显示多余的副本占了多少空间；明确选择保留副本后，即可选中多余的副本并移到回收站。
- **与之前的扫描比较**：把扫描保存为 JSON，之后就能看出哪些文件夹变大、变小、新增或消失。
- **文件类型**与**文件新旧**：按扩展名与种类（图片、视频、压缩包…），以及按最后修改时间统计占用的空间；双击一行就列出它最大的文件。
- **安全地释放空间**：“移到回收站”每次都会先询问，不会永久删除；移动前会在后台核对项目，之后重新扫描受影响的文件夹。
- **导出**文件夹列表或最大的文件为 CSV（可用 Excel 打开），或把文件夹树导出为 JSON。
- **English、繁體中文、简体中文、日本語与 한국어**，随时切换；内置“使用说明”。
- 链接与目录联接会列出来，但不会进入计算，所以不会重复计算，链接形成的循环也不会让扫描停不下来。无法读取的文件夹列在“无法读取”标签页，不会中断扫描。

## 安装

FileTree 可在 Windows、macOS 与 Linux 上运行。

**Windows，不需要 Python**：从 [Releases](https://github.com/JeffreyChen-s-Utils/FileTree/releases) 页面下载 `FileTree-<版本>.exe` 直接运行，不必安装。

从下一次发布起，同一页也会提供 `FileTree-<版本>-windows-standalone.zip`。解压**整个文件夹**后运行其中的 `FileTree.exe`，启动较快；DLL、插件及翻译文件都要保留在旁边。单文件 EXE 较方便携带，但每次启动都会先解压内含文件。两种形式都不需要 Python。

下一次发布流程也会从完整独立程序文件夹构建 `FileTree-<版本>-windows-x64.msi`。它需要管理员批准，为所有用户安装至 Program Files，添加开始菜单快捷方式，并支持通过 Windows 升级／卸载。安装包 CI 使用全新可丢弃测试数据。独立的 Desktop builds CI 会实际编译独立程序、保留 ZIP／MSI，并在可丢弃的 Windows 主机按全部内容哈希核对安装、包版本升级与卸载。原生核对已通过升级后全部 104 个文件、快捷方式、来源保留与完整移除。包升级只在相同编译内容添加验证标记；保留原始输出且不启动程序。`tools/prepare_packages.py` 使用实际 MSI／ZIP 哈希与只读 MSI 元数据生成 winget、Scoop、Chocolatey 审阅草稿。CI 保留草稿，发布附上 package-drafts ZIP。本地原生 winget 验证已通过。草稿尚未上架，发布网址须有匹配的已发布产物。签名与商店提交仍需要所有者的证书／账号。

Desktop builds CI 也会在 Ubuntu 22.04 准备完整 x86_64 Linux AppImage，在 macOS 15 准备 arm64 `.app` ZIP。原生解压比较完整运行时／包，并保留来源哈希／标识，不启动程序。CI 保留开发产物与证据七天。正式发布附件受 `FILETREE_POSIX_RELEASE_VERIFIED=true` 控制，须先完成进度项目 #4 的 macOS 验证。Developer ID 签名／公证与 Finder／系统授权仍未验证。编译运行时 wheel 锁覆盖原生 Windows／Linux／macOS，保留固定版本与哈希验证。macOS 构建直接绘制原生多尺寸 ICNS，无需外部 PNG 转换。打包把编译输出的 `start_file_tree.app` 复制成 ZIP 内独立核对的 `FileTree.app`。原生打包命令见 [Nuitka 指南](../nuitka.zh-CN.md)。AppImage 登录注册使用临时挂载外的原始可执行文件，请将该文件保留在注册位置。

**有 Python 3.10 或更新版本**，从 PyPI 安装：

```bash
pip install je_file_tree
je-file-tree
```

或从源代码运行：

```bash
git clone https://github.com/JeffreyChen-s-Utils/FileTree.git
cd FileTree
pip install -r requirements.txt
python start_file_tree.py
```

`python -m je_file_tree` 的效果相同。

要把 FileTree 给没有安装 Python 的人使用，可以用 Nuitka 编译成程序文件夹或单个 `.exe`：命令与每个选项的用途请见 [nuitka.zh-CN.md](../nuitka.zh-CN.md)。

## 使用方法

1. **选择要扫描的地方**：在起始页点“选择文件夹…”或其中一个磁盘、把文件夹拖到窗口上，或在上方的输入框输入路径后按 Enter。也可以从命令行直接开始扫描：`je-file-tree D:\Projects`（或 `python start_file_tree.py D:\Projects`）。
   拖动文件夹会在原位置扫描，且只接受复制操作；即使用 Shift 请求移动，也会保留来源。
2. **边扫边看**：文件夹树会立刻出现，FileTree 一边加总，最大的文件夹一边往上排；最大的文件与文件类型在扫描结束时补上。随时可以点“停止”（或按 Esc）结束扫描，已经读到的部分会留下来并标示为不完整。
3. **找出占空间的东西**：最大的文件夹排在最上面。点文件夹旁的箭头看里面的内容，或在右边的图表里浏览。

### 看懂结果

| 位置 | 告诉你什么 |
|---|---|
| 文件夹树 | 大小、“占用空间”（实际占用的空间：按整个簇计算，通常比大小多一点；压缩文件较少，只在云端的文件是 0）、“占上级比例”（占上一级文件夹的比例）、里面的文件数与文件夹数、最近一次变动的时间 |
| 图表 | “方块图”：每个文件一个方块，大小代表占用的空间；每个文件夹顶部有名称和大小。太小的文件合并成灰色斜线方块。“层数”决定显示深度，“颜色”可按文件类型或文件夹上色。“条形图”：当前文件夹里每个项目一个条形，附大小与比例。“旭日图”：当前文件夹在中心，每深一层就是外面一圈；点中心回上一级。“树状图”：文件夹卡片附磁盘占用大小与占父文件夹的比例；点加号展开分支，点“其余文件夹”加载更多，可切换左右或上下方向、按 Ctrl＋滚轮缩放并用滚动条移动。双击文件夹聚焦，点“上一级”返回；四种图始终显示同一个文件夹，FileTree 会记住选中的图表和树状图方向 |
| 最大的文件 | 最大的 1,000 个文件；在筛选框输入文字可以缩小列表，双击可以在文件夹树中找到那个文件 |
| 搜索 | 名称含有输入文字的文件和文件夹；模式（`*.mp4`）要匹配完整名称，多个模式用 `;` 分开（`*.iso;*.zip`）；搜索框下方的条件可以缩小范围，也可以单独使用：大于或小于某个大小、最近一周／一个月／一年内改过或超过一、二、五年没动、文件类型、只有文件或只有文件夹；搜索可以取名保存，之后再选回来；列出最大的 1,000 个匹配项目，并显示全部的数量和总大小 |
| 清理 → 建议 | 内置规则须符合文件年龄与路径／项目依据，提示会说明风险与重建方式。不确定组须手动审查，默认不勾选；较低风险缓存可整批送审，包存储库不列入。“选项 → 清理策略”控制规则、文件年龄及独立的排除项 |
| 清理 → 重复文件 | 用开头／完整哈希找出相同大小的文件（硬链接只算一份），默认最低 1 MB。每组明确选择保留副本，核对路径与估计，再选中已核对的多余副本供 Delete，或另外检查 **将多余副本改为硬链接…**（没有回收站副本，后续变化共享）。已更改、受保护、未验证及硬链接组保持原样 |
| 文件类型 | 每种扩展名占用的空间；在表格上方选一种类型就只显示那一类，双击一行会列出那种文件里最大的几个 |
| 文件新旧 | 按最后修改时间（一个月内……超过 2 年）统计占用的空间；双击一行会列出那一段里最大的文件 |
| 无法读取 | FileTree 没有权限读取的文件夹；里面的内容不会算进去 |

### 释放空间

在任何项目上点右键，可以打开它、在文件管理器中显示、复制路径、在图表中显示、在 FileTree 以外改过东西之后重新扫描这个文件夹（其余结果不变）、只扫描这个文件夹，或移到回收站（macOS 与 Linux 是“废纸篓”）。要一次移走好几个项目，在文件夹树、“最大的文件”或“搜索”列表里用 Ctrl+单击或 Shift+单击选中，只会询问一次，并列出它们和总大小。FileTree 移动任何东西之前都会先询问，而且不会永久删除。系统与程序的文件夹（Windows 文件夹、Program Files、AppData 里的程序设置、用户的个人文件夹，以及 macOS 与 Linux 上对应的位置）会说明原因并多问一次；临时文件夹与缓存不会，因为那正是要清理的东西。

移动每个项目前会核对扫描记录的文件身份、类型、大小、时间、当前父路径、解析后的保护状态与文件夹内容。已更改、不存在或扫描不完整的项目会跳过并说明原因；移动、跳过与失败分别计数。“停止”可取消剩余项目；完成后会重新扫描受影响的父文件夹。状态栏显示移动容量，清空回收站后才增加可用空间。记录文件身份会增加扫描时间与内存，Windows 尤其明显。

移动失败时，后台诊断会列出观察到打开文件的程序及 PID（Windows Restart Manager 或 Linux `/proc`），不会自动关闭程序。文件夹诊断最多查询 256 个已扫描文件；无法访问的进程、目录句柄及其他失败原因可能未知，观察到占用程序也不能证明它就是失败原因。

点击“选中这一组”或“全部选中”会在确认移动前打开审查队列，逐项显示路径、规则、原因、日期、逻辑与分配大小、保护状态及删除后果；表格下方会显示所选项目的完整说明。可以取消勾选以保留项目，或打开所在文件夹。父项目与子项目重复选择时只保留最外层。后台估计会把硬链接的共享分配空间只算一次，仍有其他名称的文件不列为可回收数据。清空回收站后可回收的文件数据以保守范围呈现，共享区块及文件夹元数据仍未知。表格下方的完整回收摘要会换行，估计或窗口宽度改变时仍完整显示。

“**文件 → 最近操作**”显示最近 500 个已确认的操作，包含移动、跳过与失败。日志只记录时间、原始路径、磁盘／文件标识、理由、结果，以及 Qt 提供的回收站位置，从不保存文件内容。仅追加的 JSONL 分段以原子方式写入应用程序本地数据目录的 `journal/`，保留 90 天／50 MB。先记录确认才执行操作；无法记录时跳过移动。结果写入失败时会尽可能停止剩余移动，并提示记录可能不完整。中断后只有确认记录的操作，其最终结果未知。CSV 导出会将主目录前缀替换成 `{HOME}`；记录回收站位置不保证可还原。保留管理只移除 FileTree 自有的日志分段，不会移除扫描的文件。

规则会说明分类、依据、最低文件年龄、风险与重建方式。近期或无日期项目不列入，文件夹按最新的子项计算（缓存／构建／临时／空文件夹 7 天、包下载／崩溃转储 30 天、安装文件 90 天）。浏览器个人设置、包存储库（`.m2/repository`、`.nuget/packages`、`.gradle/caches`）及仅名称像缓存／构建的文件夹不列入。项目输出须有项目描述文件，Python 缓存须有生成文件的依据。临时文件、崩溃证据、下载、构建输出及空文件夹使用“手动审查”，默认不勾选且不包含在“全部选中”中。较低风险的缓存仍须审查与确认。

“**选项 → 清理策略**”可启用／停用每条规则、设置最低文件年龄，或排除绝对路径／名称模式（每行一个）。排除子项也会避免把其父文件夹整个列入。这与“扫描时跳过”独立：不提出清理建议的数据仍计入磁盘用量。未修改时保留内置规则。保存前会根据当前扫描预览增加／移除的候选数量与逻辑容量，修改设置会使预览失效。策略保存在 QSettings，仅接受经验证的第 1 版 JSON 导入（支持的规则、布尔开关、0–36500 天与排除项）。已保存的设置无效时会停用建议，直到重新审查；手动审查风险不能调低，也不支持自行执行的规则。

### 看看哪里变大了

“**文件 → 扫描历史…**”显示此根目录保留的容量折线图及最多 1,000 条扫描。选中先前扫描即可打开已有的“变化”选项卡，不必选择文件；Ctrl+C 可复制行。历史默认启用，**所有根目录合计上限 1 GiB**。“**选项 → 扫描历史设置…**”可停止未来保存或调整上限（1–16384 MiB），降低上限会在下次保存时应用；关闭后仍可读取已有历史。整个扫描将文件夹路径、名称、容量与覆盖范围，以兼容的扫描 JSON 存入应用本地数据目录的 `history/<root-path-hash>/`，不含文件内容。停止的扫描及局部重扫不保存；含读取错误的完成扫描标记为不完整，缺少文件夹不代表已删除。按名称计算的分配量分别计入硬链接名称，比较描述元数据而非验证内容。只从所有根目录按时间移除识别为历史的元数据，以符合上限；拒绝链接目录、链接文件及其他数据。单条快照超过上限时会跳过并显示错误，扫描仍可完成。保存／读取失败会显示；停止或关闭会等待后台读取结束。历史仅存本地，不计划扫描，也不移除记录中的源文件。

用“**文件 → 导出 → 文件夹树（JSON）**”把扫描保存起来。之后重新扫描，选“**文件 → 与之前保存的扫描比较…**”打开那个文件，就会出现“**变化**”选项卡，列出每个有变化的文件夹之前和现在的大小，变大最多的排在最前面；新的文件夹标示“新增”，消失的标示“已不存在”。在点“结束比较”之前，之后的重新扫描都会继续比较。文件夹是按它在扫描文件夹下面的路径对应，所以也可以拿来跟放在别处的同一份数据（例如备份）比较。

### 小知识

- 大小是文件的实际大小，按二进制单位计算（1 KB = 1,024 字节），和 Windows 资源管理器相同；可以在“视图 → 大小单位”改用固定的单位。
- 在 Windows 上，FileTree 启动时会像 TreeSize 一样请求管理员权限，受保护的文件夹也能读取。拒绝的话它照常以普通权限运行，读不到的文件夹列在“无法读取”标签页，那里有“以管理员身份重新启动”按钮（“文件”菜单里也有）。不想每次被问，可以关掉“视图 → 启动时请求管理员权限”。
- “最大的文件”、“文件类型”与“文件新旧”默认统计整个扫描范围；点这几个选项卡右上角的“只看选中的文件夹”，就会改为跟着文件夹树中选中的文件夹。
- 默认会计算隐藏文件；关掉“视图 → 包含隐藏文件”，下次扫描就不会算进去。
- 清理建议会显示已知容量，以及跳过、无法读取、尚未扫描的文件夹数；省略部分的容量为未知。不完整的分支不会被整体建议清理，也不会被视为空文件夹。扫描不完整时禁用“全部选择”；清理前请重新扫描相关分支。刷新时会清除过期建议。
- 要让某些文件夹每次都不扫描，把它们加进“视图 → 扫描时跳过”：像 `node_modules` 或 `*.cache` 这样的名称会跳过所有同名的文件夹，路径只跳过那一个文件夹。跳过的文件夹会以灰字列出，大小为 0。
- 语言、大小单位、窗口布局与最近扫描过的文件夹都会记住（Windows 上保存在注册表的 `HKEY_CURRENT_USER\Software\JE-Chen\FileTree`）。

重复文件的总量标为“逻辑大小”。每组请选择文件行并按“保留选中的副本”，列表会标明保留副本的完整路径，并保留名称、日期与父文件夹供比较。估计按这些选择显示不重复分配空间及清空回收站后可回收数据的保守范围，未决定的组保持未知。“选中多余的副本”只包含范围、保护状态、更改与硬链接名称（含扫描范围外的名称）核对成功的组。确认后会重新完整哈希并核对该组所有文件；核对失败时整组保持原样并要求重新扫描。“停止”取消剩余工作。系统移动失败仍可能造成部分批次完成；回收站移动不是整组原子操作。压缩／稀疏文件按分配大小计算，哈希不打开已知的云端占位文件。共享区块及文件夹元数据仍未知，移到回收站本身不释放空间。隔离磁盘实测仍待完成。

相同文件夹会列在文件组上方，以“副本 = 原始文件夹”显示，沿用搜索所得的哈希，不会再读取内容。每个非空文件都须有已验证哈希，且相对名称、大小、哈希与空文件夹结构须相同。未哈希的小文件／独有文件、链接及不完整分支会阻止文件夹配对。已包含在父配对中的子项不重复列出，其他位置的额外副本仍会列出。这些行仅比较搜索快照，不代表可移除文件夹。

### 容量明细

Windows 的“**文件 → 已安装程序…**”列出最多 1,000 个卸载注册项及识别到的 Steam／Epic 游戏名称，并显示完整数量及元数据失败情况。只读查询 HKLM／HKCU 的 32／64 位视图，不修改注册表。`EstimatedSize` 是报告的 KiB 估计；文件夹逻辑／分配量只取自当前扫描中完全匹配且不是链接的文件夹。缺少位置及无法读取／跳过范围保持未知或不完整。Steam 清单取自扫描中的 `steamapps`，也会读取 Epic 固定的 `%PROGRAMDATA%/Epic/EpicGamesLauncher/Data/Manifests`，可核对另一磁盘的游戏名称。每份清单限 1 MiB，核对扫描及打开文件的快照，跳过已知云端／链接状态，并报告格式错误或变化。共享／嵌套安装文件夹可能重叠，请勿合计行或推算卸载可释放空间；部分打包／便携式应用不会列出。双击选中匹配的树状文件夹，Ctrl+C 复制行。按钮以固定 URI 打开 Windows 已安装应用设置，不执行注册项的卸载命令。停止或关闭会等待后台工作结束并忽略取消的回复。此视图仅限 Windows。

账本也会识别绝对路径的自定义 `XDG_DATA_HOME/Trash`；相对路径设置会使用默认数据目录。

文件夹树上方会显示系统已用／可用空间，以及硬链接只算一次的文件分配估计。“容量明细”会区分按名称计算的分配、硬链接重复量、已读取的回收站数据（已包含）、跳过／无法读取的范围及其他挂载磁盘。完整扫描整个磁盘时，会把无法解释的差额列为“无法归账”。仅扫描文件夹、扫描不完整、缺少标识信息或分配估计超过系统已用空间时，都无法核对整个磁盘。文件系统元数据／保留空间、跳过的字节及其他磁盘的总量保持“未知”，而非 0。系统容量與文件快照不是同时测量，共享区块、快照与 Windows 分配估计会影响差额；自建 ext4 容量／保留空间及硬链接／稀疏文件回收案例已通过 CI；自有 NTFS／APFS 案例也已通过原生 CI，独立共享／保留字节仍为未知，因此账本只称为估计。Linux 回收站的逻辑内容量，与账本含内容及收据的分配量范围不同，均不是额外计入的容量。命令行的扫描记录也会在 `capacity` 字段包含这些数字。跨磁盘的文件夹挂载点只列出、不继续扫描。Linux 也会在遍历前及返回结果前读取 `/proc/self/mountinfo`，跳过明确的文件夹挂载点，包含同设备 bind mount 及经祖先别名到达的路径。挂载边界列在“无法读取”，跳过字节保持未知；直接选择挂载文件夹作为扫描根目录仍可扫描。挂载表丢失或格式错误时，会在遍历前停止。macOS 也会查询有上限且完整的原生 getfsstat 挂载表，以 fstatfs 标识检查固定每个文件夹描述符；挂载表格式错误／截断或范围／根目录挂载变化时，拒绝完整扫描结果。其余 POSIX 系统仍采用设备边界检测；macOS 的原生同设备案例仍未验证。Linux 会在读取条目元数据期间保持文件夹描述符打开，检查挂载 ID 与原有标识信息；相关挂载点或根目录挂载变化时，拒绝返回成功结果，请按错误提示重新扫描。失败扫描不写入历史；所选范围以外的挂载变化不会中止扫描。Linux 需要可读取且含挂载 ID 的 proc 元数据（内核 3.15 以上）。内核 5.8 以上且 libc 支持时，使用经结果标志确认的 statx 描述符查询，避免每个文件夹额外打开与解析 proc 文件；不支持、拒绝或缺少结果时改读 fdinfo。这仍不是文件系统事务快照。私有 Linux 命名空间的自建静态同设备 bind mount 已通过 CI；CI 也测试打开文件夹前后的实时 bind mount，并记录描述符防护的耗时。

在文件夹树的列标题单击右键，可选择显示的列，设置会保留。名称列保持显示并默认为可读宽度，额外列可水平滚动。“**占磁盘比例**”可选择显示，与“占上级比例”并列，按逻辑字节除以系统报告的磁盘总容量。容量尚未获取、文件夹树变更后及其他磁盘项目会显示未知；硬链接名称仍分别计算，因此不是分配或可回收空间。

64 位 FreeBSD 12 以上也使用有上限的原生 getfsstat 挂载表及固定描述符的 fstatfs 标识。未知 ABI 版本或挂载边界变化时，拒绝返回完整结果。独立且可丢弃的 FreeBSD 14.3 CI 虚拟机只测试新建、只读的 nullfs 挂载，涵盖一／四个工作线程，以及打开文件夹前后新增挂载；JSON 记录来源保留、卸载与清理确认。[已审查的原生证据](../docs/updates/mounts-20261009-freebsd.json) 已确认上述案例、源与底层内容保留及清理完成。FreeBSD 为 nullfs 分配不同设备 ID，这个案例不能证明同设备行为。工具拒绝桌面主机，不接受已有挂载选择参数。

阶段 JSON 以明确 UTF-8 编码原子写入；即使最初的证据写入失败，仍会进入自有测试数据的清理流程。

## 不开窗口的命令行

命令行入口只使用核心，不会加载 Qt。CSV／JSON 导出与窗口相同，以原子方式写入；比较会列出绝对变化最大的项目，最多 `--limit` 项（默认 1,000）。标准输出是逐行 JSON，使用固定字段（`file-tree-cli/1`）并包含扫描覆盖范围；比较会增加 `changes` 记录。错误以 JSON 写到 stderr。默认两个工作线程，可用 `--workers`、可重复的 `--exclude` 模式及 `--no-hidden` 控制扫描。

```bash
je-file-tree-cli scan D:\ --folders folders.csv --largest largest.csv --json tree.json
je-file-tree-cli scan D:\ --compare old.json --limit 20
python -m je_file_tree.cli scan D:\ --exclude node_modules --workers 2
python -m je_file_tree.cli scan D:\ --count-hard-links
python -m je_file_tree.cli scan C:\ --also D:\ --json drives.json
```

退出代码：**0** 覆盖范围完整、**1** 不完整（包含排除及无法读取的项目）、**2** 参数错误、**3** 扫描／比较／导出 I/O 错误或保存的扫描格式无效、**130** 已中断。Ctrl+C 会停止扫描并导出已读取的部分；再次按 Ctrl+C 则立即中止。每份导出独立完成原子写入，后续导出失败不会撤销先前完成的报告。命令行不提供删除或自动清理。

SonarCloud 自动分析使用 [.sonarcloud.properties](../.sonarcloud.properties) 区分主要源与 `test/`。程序、工具、工作流程及版本控制元数据仍纳入分析，未设置排除或修改质量门槛。服务文档要求从默认分支启用，因此只在 dev 新增文件不能证明额度问题已解决；须以最新 API 结果确认分析完成及质量门槛。

SonarCloud 项目经所有者同意改为公开（[配置验证](../docs/updates/sonar-20261009-public.json)）。经所有者同意的[本地 CLI 路径审核](../docs/updates/sonar-20261009-cli-review.json) 保留依当前操作系统权限，明确指定扫描根目录、比较文件与报告位置的功能。六项已接受的路径告警及各自理由仍保留在 SonarCloud。合并前须确认当前提交的分析已完成，且质量门槛通过。 CI 与 Linux 桌面容器使用 `.github/requirements/` 版本控制中的版本／哈希锁定文件，只安装 wheel；依赖变更时须一起更新 runtime 与 test 锁定文件。桌面镜像默认使用对应的非管理员用户。 文件管理器启动时会拒绝 Windows 路径中的非法引号／控制字符，并以单一绝对路径参数交给 macOS open。MSI 版本限用有范围的数字字段。Linux 桌面验证固定将证据写入 `/evidence`，通过私有管道取得 Xvfb 就绪信号／显示编号，并确实等待自建子进程结束。 备用测试入口只接受固定的私有 Linux 测试数据，不提供 CLI 目标／输出选择参数。

只使用标准库的 `core/mft.py` 基础模块会有界限地解析 NTFS 3.1 原始 FILE 记录、名称、属性列表、非驻留区段及大小／分配元数据。它拒绝不完整或不支持的记录、保留重用序号，而且不保留驻留的主文件／命名流内容。Python API 可明确指定 `ScanOptions(experimental_mft=True)` 进行顺序元数据审核，普通扫描仍为默认。`core/mft_reader.py` 使用已有的管理员令牌，提供本地固定 NTFS 磁盘的有界限只读访问，核对磁盘几何及扩展记录的序号／归属，不请求提权或修改权限。

`core/windows_directory.py` 在普通目录访问检查后提供有界限的原生可见名称／文件标识；拒绝变更、重解析及云端范围，停止时关闭自有句柄，调用方须固定上级目录。候选树要求普通目录可见性及每个路径的无跟随 stat 权限，再核对原始名称／父级／序号／日期／链接数／大小。分配、所有者、选项与链接边界沿用普通 Node 规则。不支持或原始数据解析失败时，舍弃候选树并核对根目录标识后重新普通扫描，进度可能重新开始。成功或取消时采用到唯一已发布的根节点。

[已审查的 Windows 原生证据](../docs/updates/mft-20261009-native.json) 在新建私有 NTFS 映像通过：238 条原始／原生目录观测、驻留容量及别名／扩展记录核对、五组实际 MFT 树形数据／选项比较、拒绝目录列出时的不完整范围与精确 DACL 还原、已计量的单一根节点取消、源／命名流／内容保留、原生符号链接完整快照／目标保留及映像清理。三组整个私有磁盘比较亦通过；Windows 管理的 System Volume Information 返回不同的列出／路径修改时间，因此回退普通扫描。这些计时属于回退测试，没有成功的整盘 MFT 样本，其中位数为 null。考虑默认启用前，仍须验证大型实际磁盘的 MFT 结果与性能；顺序审核不保证加速。

原始驻留 DATA 不占用额外数据簇，原生 `FILE_STANDARD_INFO` 仍可能报告包含对齐填充的驻留空间。解析器分别保留逻辑长度与有界限的驻留值容量；诊断工具分别记录原始／原生分配观测值。

私有 Windows 验证工具另在 512 MiB 镜像比较新建稀疏文件的 8／16／32／48／64／96 MiB 逻辑长度；`python tools/validate_windows_sparse_trash.py --output sparse-trash.json` 使用现有管理员权限，在新建固定 2 GiB VHDX 重复比较。只接受这两种全新私有磁盘容量，格式化前核对大小。记录完整来源哈希、Qt 返回、有限的私有回收站列表、原生总计、只读观察的磁盘偏好及 OS 可用空间变化。缺少原生列表时保持未知，不授权清空。不更改偏好或视为有效配额；原生结论需以 CI 证据确认。

每次批准的 Windows 来源移动前，FileTree 会拒绝未知／禁用的回收偏好、不完整的来源具名大小、无法核对的原生回收站数据，以及选中项目加上当前回收站内容超过观察到的各磁盘上限与 1 MiB 预留空间的情况。范围必须是当前的本地固定 NTFS，具有驱动器根目录与卷 GUID。再次核对设置与磁盘，不更改注册表偏好。拒绝时保留来源、持久记录跳过原因并更新上级文件夹；重复文件清理及复制后移至回收站也适用。通过此保守检查只是观察结果，不是有效配额或保留内容的保证；OS 设置／回收站仍可能同时更改。原生私有诊断会对被拒绝的文件执行实际后台任务，核对完整哈希／身份及持久跳过状态，再进行独立的原始 Qt 测试数据诊断。

原生 Windows 11／Qt 6.11.2 CI 在两种 512 MiB VHD／VHDX 重现大型稀疏文件差异：8–48 MiB 名称有实际 $R／$I 内容／回执列表；64／96 MiB 名称的 Qt 返回成功，但无原生回收站项目或内容，且立即释放 65,536 分配字节。新建 2 GiB 磁盘则保留全部六种长度。观察到的 MaxCapacity 偏好分别为 49 与 203，与逻辑长度配额界限吻合；有效配额及 Shell 后备机制仍未证实。三个自有磁盘均确认分离及清理。缺少回收站的结果保持未知。正式回收流程会在 Qt 操作前，保守拒绝未知／停用的偏好、不完整大小及观察到的容量超限。原生 CI 已验证实际工作线程保留 64／96 MiB 来源、完整哈希／快照不变，并留下持久的跳过记录，未调用 Qt 移动。通过这项检查仍不保证能从回收站还原。

```powershell
py -3 tools/validate_windows_volume.py --output windows-volume.json
py -3 tools/validate_windows_volume.py --kind vhd --output windows-volume-vhd.json
```

CI 工具另以 `--kind vhd` 建立全新 VHD 测试镜像，默认仍是 VHDX。有客户机数据的 VHD 与 VHDX 原生验证均已通过，确认分离／清理；本次磁盘文件分配量分别减少 31,518,720 字节与零。两种格式分开执行步骤，避免后续成功命令掩盖前一个失败。自有测试设置及分离完成后，以只读查询仍固定原始身份的镜像，取得新的检查标识符，创建时与检查时的标识符分别记录。正式批准／执行的标识符核对保持不变。只写入新的客户机文件、硬链接与命名数据流，哈希完整内容，分离／关闭自有 handle，核对并固定原始镜像／临时目录身份后，使用正式运行状态／预览／原生执行及持久操作日志。只将该标识符重新以只读方式挂载，不分配驱动器盘符、不格式化，再比较完整客户机名称范围、文件身份／链接数／长度及主内容／数据流的完整哈希。后续验证或只读分离失败会保留镜像，只有完整证据确认清理。不接受已有镜像选择器或真实用户客户机。
