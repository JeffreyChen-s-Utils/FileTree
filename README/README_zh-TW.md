# FileTree

**看看磁碟空間都用到哪裡去了。** FileTree 會掃描一個資料夾或整顆磁碟，把裡面每個檔案的大小加總，先列出最大的資料夾和檔案——用資料夾樹、彩色的方塊圖和最大檔案清單呈現。找到不需要的東西時，直接在視窗裡把它移到資源回收筒。

![FileTree 顯示一個使用者資料夾：左邊是資料夾樹，右邊是方塊圖](../docs/images/main_window_zh-TW.png)

在樹狀清單、搜尋或最大檔案清單選取實際項目，按右鍵 → **移至資料夾…** 或 **重新命名…**。預覽視窗列出每個最外層來源／目的地及拒絕原因，最多選取 1,000 個項目。選擇現有資料夾，或使用字面 `{name}`、`{stem}`、`{ext}`、`{n}` 代換的檔名模式。名稱已存在時預設 **略過**；明確選擇編號尾碼可預覽實際替代名稱。變更選項後確認失效，請重新按 **預覽路徑**。**套用已檢視的路徑…** 顯示預設為「否」的純文字詢問，詳細資料列出每組可執行路徑；拒絕／未變更的列仍顯示並略過。執行時固定選項，重新檢查完整來源記錄與上層身分，以原生同磁碟不覆寫重新命名操作，不複製或覆寫。拒絕受保護、連結、特殊、已知無法取得、已變更或跨磁碟項目。停止／關閉須等目前重新命名完成，保留已完成的變更。逐項錯誤及實際路徑保持可見；操作後記錄不符時嘗試不覆寫地復原，失敗則回報保留的目的地。同時發生的檔案系統變動不具交易保證。範圍外的目的地上層在專屬背景工作重掃，顯示數量／錯誤；關閉後重建目前根目錄，更新範圍內兩側上層，並清除舊容量中繼資料。取消重掃的結果仍可見。Python API 提供 `namespace_moves.prepare_namespace`／`execute_namespace`、已移動／略過／失敗結果及兩側上層路徑。macOS 原生行為仍未驗證；跨磁碟驗證複製為另一項待辦。

**選項 → 觀察到的硬連結只計一次** 預設關閉，設定會保存並由後續掃描記錄。另提供計入的邏輯／磁碟分配總量，保留具名檔案長度、分配與數量。摘要顯示計入總量、觀察到的別名及未知記錄；標題選單提供預設隱藏的 **計入大小／計入磁碟大小** 欄位。觀察到的路徑排序第一個名稱計入位元組，其他名稱僅在計入欄位記為零。圖表及圖例使用計入總量；最大檔案／搜尋／類型／檔齡／擁有者列表及上層／磁碟占比保留具名計量。未知／不一致中繼資料保留具名估計，共用資料區段與資料夾中繼資料仍未知。此模式的分支重掃及移到資源回收筒後會重掃完整範圍，原計入名稱離開後轉由剩餘名稱計入。執行中的工作保留原選項。CSV 新增 `accounted_size_bytes`、`accounted_allocated_bytes` 與 `hard_link_accounting`（0／1）；資料夾 JSON 新增計入值及模式旗標，保存比較／歷史仍保留具名 `size`。HTML／XLSX 報告保留具名表格，另有計入的項目／摘要欄位。命令列接受 `--count-hard-links`，輸出計入位元組總量與 `hard_link_accounting` 中繼資料。停用時，計入欄位沿用具名估計。Python API 使用 `ScanOptions(count_hard_links=True)` 與 `Node.accounted_size/accounted_allocated`；變更記錄樹後請在背景工作重新執行 `account_hard_links`。沿用既有 stat，不增加 OS／內容讀取。原生自建兩個名稱的測試保留 2 MiB 具名總量、1 MiB 計入總量、兩個實際檔案長度及一個別名。

掃描完成後，展開已記錄的 **ZIP／7z／RAR** 檔案，即可按需讀取內容清單。標為 **［虛擬］** 的項目顯示宣告的未壓縮大小，不加入磁碟總量、圖表、匯出或檔案操作。不會解壓縮，也不開啟巢狀壓縮檔。ZIP 使用標準程式庫，7z 使用已安裝的 `py7zr`；RAR 使用 `rarfile`，需要 PATH 上的 `unrar` 或 `bsdtar`，缺少時保留為一般檔案並在工具提示說明原因。已變更、無法讀取、損壞或標頭加密的檔案也保留為一般檔案。拒絕已知雲端佔位檔及來源連結。內容中的連結、跳出範圍／絕對名稱、重複衝突及過長／過深名稱會略過，並顯示數量。清單上限為 100,000 個項目、1,024 字元名稱、128 層及累計 32 MiB 解析讀取；解碼前核對 7z 標頭宣告的解碼大小。最多同時讀取兩個檔案。來源檔案按右鍵 → **停止讀取此壓縮檔** 可停止；停止或關閉須等目前解碼呼叫結束。重新掃描可重試；新掃描或樹狀清單變更會使舊回覆失效。已展開資料夾的文字篩選只涵蓋實際檔案，篩選期間隱藏虛擬項目。預覽只讀取標頭，不讀取內容，因此不驗證 CRC 或實際解壓縮大小。

在 **清理 → 重複檔案** 選擇 **相似照片** 與最低檔案大小（預設 1 MiB），再按 **尋找相似照片**。此獨立搜尋以已安裝的 `Pillow` 解碼已記錄的圖片類型，套用 EXIF 方向並只看動畫第一格，從灰階 9×8 圖片比較 64 位元差異雜湊。漢明距離可設為 0–16（預設 4）。每組與第一張觀察到的圖片保持在門檻內，組內其他圖片彼此的距離可能更大。色彩、單色圖片或不同場景可能碰撞，請比較縮圖與原圖。這是視覺候選清單；明確選擇保留副本／多餘副本及回收量估計仍只提供給精確重複檔案。手動操作選取的檔案沿用既有確認／保護流程。背景工作拒絕已變更、連結或已知雲端檔案，略過不支援、損壞或超過限制的圖片並顯示數量；每個已記錄的硬連結識別只選取一個名稱。成功的雜湊上限 100,000 筆，來源上限 128 MiB、像素上限 4,000 萬，顯示的圖片列／縮圖上限 1,000 筆。停止、新掃描、切換模式或樹狀清單變更會使舊回覆失效；關閉會等待目前解碼呼叫結束。縮圖只存記憶體，來源位元組不變，不連線或自動操作檔案。

**選項 → 量測 Windows 逐檔磁碟大小** 預設關閉，套用至後續完整／分支掃描，啟用後請重新掃描。此功能以不跟隨連結的中繼資料控制代碼查詢 `FILE_STANDARD_INFO`，核對完整的 64 位元磁碟／128 位元檔案識別碼（Python 3.12 之前使用舊版 stat 識別碼）、大小與修改時間；即使未顯示一般壓縮旗標，也能量測一般檔案與 XPRESS／WOF 的分配大小。已知雲端／離線檔案仍不查詢並記為零，不支援、權限不足或記錄已變更時採用已說明的大小估計值。逐檔查詢會增加掃描時間，不讀取檔案內容；共用資料區段與資料夾中繼資料仍未知，硬連結仍按各名稱計算。預設掃描對一般檔案保留簇估計值。原生自建測試檔案通過 NTFS／XPRESS8K 壓縮及解壓縮內容核對，逐檔量測的重新掃描記錄了 2 MiB XPRESS 檔案的 73,728 位元組分配大小，該檔案未顯示一般壓縮旗標。

Windows 已掃描資料夾的右鍵選單提供 **NTFS 壓縮…**。可取消的唯讀預覽顯示最大的 1,000 個已記錄日誌／文字／程式碼／執行檔／可能未壓縮影像候選項目、全部數量及邏輯大小／具名磁碟分配。可能節省量為 **0–候選項目的磁碟分配**，不保證壓縮率或可釋出空間。可選 NTFS、XPRESS8K（少修改的資料）或解壓縮；解壓縮會列出安全的已記錄類型，不依賴壓縮旗標。**處理列表中的檔案…** 以預設否的問題顯示範圍、模式、列表數量與邏輯位元組。僅處理列表檔案，不處理全部候選項目，也不變更資料夾預設值與列表外檔案。原生工具僅適用目前的本機固定 NTFS 磁碟，重新核對記錄的識別碼，並以控制代碼防止所有上層資料夾與檔案遭重新命名／刪除。拒絕連結、已知雲端／離線、稀疏、隱藏／系統、硬連結、受保護及已變更／未知項目。不使用 shell、萬用字元或 `/s` 遞迴；解壓縮會執行 `/u` 與 `/u /exe`。壓縮可能降低寫入速度，解壓縮需要可用空間。停止／關閉會終止並等待命令；先前／目前檔案可能保留部分變更。結果顯示核對成功的已知前後分配、未知數量及前 20 筆錯誤。關閉後會暫時啟用逐檔磁碟大小量測，重新掃描完整範圍／分支；之後的手動掃描仍依選項設定。預覽不讀取檔案內容，確認後的原生操作可以讀取。操作前按兩下可選取記錄的檔案，Ctrl+C 複製列表。原生新建暫存檔案驗證保留 SHA-256、還原分配、拒絕硬連結，且 junction 外的對照檔案未變更。

**使用者** 分頁以整份掃描的檔案擁有者加總，顯示最大的 1,000 組，並保留全部群組／檔案／位元組數，欄位含邏輯大小、具名磁碟分配、檔案數及邏輯大小占比。POSIX uid 使用掃描已讀取的 stat；Windows 的 **選項 → 記錄 Windows 檔案擁有者** 因逐檔安全性查詢成本較高而預設關閉，啟用後請重新掃描，設定套用至後續完整／分支掃描。共用不可變的 uid／SID 識別碼增加一個擁有者欄位（量測每個節點增加 8 位元組）。Windows 唯讀查詢一般檔案的擁有者 SID，略過連結及雲端／離線檔案，查詢後重新核對記錄的中繼資料。未啟用、無權限、缺少或已變更的擁有者獨立列為 **擁有者未知**，掃描不完整也會標示未讀取資料。開啟分頁才會在可取消的背景任務加總並查詢帳號名稱，名稱無法解析時保留 uid／SID。停止、切換分頁、新掃描及關閉會丟棄已取消回覆，關閉等待所有工作結束；移動及分支重新掃描會使總計失效。**更新記錄總計** 僅重新彙總掃描，擁有者已變更時請重新掃描。支援 Ctrl+C 與目前列表 CSV 匯出。資料夾擁有者不會套用至內含檔案，硬連結仍按各名稱計算，磁碟分配仍為估計值。擁有者不能證明實際使用或移除權限，此分頁不會產生清理操作。僅含資料夾的 JSON／歷史記錄不保存檔案擁有者。

**選項 → 記錄檔案存取／建立時間** 預設關閉，適用於之後的完整與分支掃描；開啟後請重新掃描。沿用已讀取的 stat，每個一般檔案快照增加 16 bytes，不新增 Node 欄位或額外時間查詢。資料夾樹標題選單提供預設隱藏的「記錄的存取時間」與「建立時間」欄位。**檔案 → 檔案時間…** 可依記錄的存取／建立時間，篩選至少多少天前的檔案（0–36,500 天，預設 730）；顯示最大的 1,000 個符合項目，以及全部符合數量、位元組與未知數量，支援 Ctrl+C、選取樹中對應項目、停止與關閉後等待背景工作結束。整棵樹的篩選在工作執行緒進行。缺少或在未來的時間保持未知；不記錄資料夾與連結時間。建立時間取 birthtime（舊版 Windows Python 缺少 birthtime 時才用 ctime），不使用 POSIX ctime。唯讀查詢 NTFS `NtfsDisableLastAccessUpdate`，包含初始化與系統管理旗標；回報停用或設定未知時，無法依存取時間篩選，仍可依建立時間篩選。登錄值可能需重新啟動，且無法證明每個磁碟實際套用的設定。其他檔案系統／提供者也可能延遲或停用 atime，背景讀取也會改變日期，記錄時間無法證明實際使用時間。此檢視不會準備清理操作。最大檔案 CSV 新增 `accessed`／`created` ISO 日期，未知時留空；僅含資料夾的 JSON／歷史不保存檔案時間。

掃描列的「**暫停／繼續**」會暫停取得新資料夾。目前的資料夾讀取會完成，資料夾樹仍持續更新；暫停時仍可「停止」或關閉視窗。最後的結果分析不能暫停。經過時間包含暫停期間，繼續時保留同一份掃描及計數。

「**選項 → 低優先順序掃描**」預設關閉，套用到新掃描。每個掃描執行緒使用 Windows 背景 CPU／I/O 模式，或 Linux nice 10 與最低的 best-effort I/O 優先順序，不影響介面執行緒。不支援的平台、權限拒絕或僅部分套用會回報；可讀資料夾仍繼續掃描。I/O 效果取決於磁碟排程器，掃描可能花較久時間。命令列及量測工具接受 `--gentle`，命令列 JSON 包含 `warnings`。

矩形樹圖與放射圖共用「**顏色 → 依修改檔齡**」，使用「檔齡」清單的範圍，並顯示由淺（近期）到深（較舊）的圖例。顏色依掃描／分析時間計算，游標移動時不會隨時鐘改變。資料夾依最新的修改記錄著色；無可用日期、未來日期與合併的小項目為灰色。這表示修改檔齡，不能判斷最後存取時間或是否未使用。

「**檔案 → 匯出**」與圖表右鍵選單可將畫面上的圖表儲存為 **PNG**，包含目前可見範圍、配色及選取狀態。長條圖與放射圖另提供 **SVG**：有數量上限的完整長條列或圓弧會繪製成向量圖形與文字，不使用放射圖的快取點陣圖。PNG 編碼與檔案寫入由匯出工作執行緒處理，以原子方式替換檔案；關閉視窗會等待匯出完成。

「**檔案 → 列印目前畫面**」（`Ctrl+P`）會開啟系統列印對話框。「**檔案 → 匯出 → 目前畫面（PDF）**」會儲存一頁 A4，依擷取畫面選擇橫向／直向。兩者將目前分頁及可見範圍等結果等比例放入可列印邊界，不拉伸或裁切；輸出是擷取的像素，捲動範圍外的項目不在其中。PDF 由匯出工作執行緒使用 Qt PDF 引擎寫入，以原子方式替換指定檔案；關閉視窗會等待完成。

圖表分頁提供可點擊的資料夾路徑與 **返回／前進**（`Alt+Left`／`Alt+Right`）。歷程保留目前掃描最近 100 次導覽；返回後開啟其他資料夾會取代前進歷程。新掃描會重設歷程，重新掃描會移除失效項目。長路徑可水平捲動，**…** 可選擇更上層的資料夾。

展開資料夾樹下的 **詳細資訊**，可查看選取項目的大小、磁碟大小、檔案與資料夾數、已記錄的修改日期，以及小型類型與檔齡分布。面板會記住展開狀態；掃描結束且面板展開時才在可取消的背景工作中計算分布，僅使用已讀取項目，未知與未來日期分開列出。更換選取項目會捨棄過期結果，關閉視窗會等待工作結束。

**檔案 → 匯出 → 目前清單（CSV）** 可儲存搜尋、重複檔案、變更、檔案類型、檔案新舊、最大的檔案、清理建議或問題清單，保留顯示的標籤、單位、篩選與排序。分組清單包含群組標題及其項目，即使已收合亦然。清單或資料夾樹取得焦點時，**Ctrl+C** 會將選取列與欄名複製成含引號的定位字元分隔文字；文字欄位仍正常複製。看似公式的文字會加上試算表保護前綴。CSV 擷取會以短批次讓出介面，透過有上限的佇列交給背景工作原子寫入；清單變更會取消匯出並保留既有目的檔案。

在 **檔案類型** 連按兩下副檔名，即可同時查看最大的符合檔案與最多 1,000 個 **所在資料夾**，包含符合類型的大小、檔案數及占全部符合位元組的比例。資料夾僅計算直接包含的檔案，巢狀資料夾不會重複計算。兩份清單在可取消的背景工作中一起計算，並遵循 **僅選取的資料夾** 範圍。變更副檔名、掃描或範圍會捨棄舊結果；**顯示全部** 可回到一般清單。依檔齡查看檔案也在背景執行。

Windows 的 **詳細資訊** 會解釋休眠、分頁與交換檔、Windows.old、資源回收筒、System Volume Information、WinSxS、Windows Update 下載及傳遞最佳化快取。辨識使用磁碟根目錄或目前 Windows 安裝的完整位置，包含其子項目，不會僅憑同名判定。按鈕開啟對應的 Windows 設定或系統工具；FileTree 不執行清理命令，也不移動這些系統管理項目。操作背景工作亦會拒絕包含它們的資料夾，並重新檢查解析後的路徑。WinSxS 加總可能包含共用硬式連結；未讀取的系統資料仍未知。

四種圖表提供輔助工具名稱、鍵盤操作說明，以及目前資料夾與選取項目的已記錄大小及數量。以 Tab 或點擊將焦點移至圖表：**方向鍵** 選取已繪製項目，**Enter** 開啟選取的資料夾，**Backspace** 返回上層。樹狀圖保留上／下選取卡片及右／左展開、收合的操作；長條圖與樹狀圖會將選取列捲動至可見位置。導覽使用有上限的圖表版面，合併或未顯示的項目可在資料夾樹查看。Alt+Left 等組合快捷鍵保持原有操作。

**檢視 → 主題 → 系統／淺色／深色** 可立即切換並記住選擇。系統模式恢復原生平台樣式與色盤；指定主題使用一致的 Qt 控制項，以及清楚的文字、選取與停用顏色。色盤或樣式變更會重新繪製圖表。方塊圖與放射圖依實際填色對比選擇黑字或白字；方塊圖僅在漸層兩端都維持至少 4.5:1 對比時保留漸層。長條圖的名稱與數值使用目前色盤，顯示在彩色長條之外。

## 功能

**選項 → 掃描執行緒數…** 設定新掃描與分支重新掃描的並行數，範圍 1–32；既有預設仍最多為 4（依 CPU 數量限制），儲存值無效時採用預設。進行中的掃描保留原執行緒數。慢速共用可能受益於較高並行數，但磁碟／伺服器在過高負載下也可能變慢，請依環境選擇。Windows 可貼上 `\\server\share` 等絕對 UNC 路徑，以目前帳戶權限存取。權限不足／斷線的分支維持不完整，歡迎頁包含此提示。目前沒有共用環境，實際 UNC／網路磁碟效能、配置與斷線驗證仍待完成。

歡迎頁、清理頁或檢視選單的 **資源回收筒…** 可審查各磁碟總量。Windows 可選取一個本機磁碟，再按 **清空選取磁碟的資源回收筒…**。兩次詢問皆列出磁碟、回報大小與項目數，並說明永久移除。背景工作重新查詢總量，拒絕總量已變動或記錄不完整的回收筒，再針對明確磁碟呼叫 `SHEmptyRecycleBinW`。這項永久移除例外僅限目前使用者的系統回收筒，不接受任意路徑或所有磁碟範圍。原生清空作業開始後不能取消，完成前停用停止／關閉與項目啟動。系統作業期間新增的項目也可能被移除。錯誤可能留下部分已清空的回收筒，會搭配重新查詢的總量顯示。完成後更新容量／回收筒中繼資料；重新掃描可更新主樹狀圖。macOS 使用下述另行檢視的 Finder 全域清空動作。驗證不會清空真實使用者的回收筒。

Linux 的同一按鈕會先在可取消的背景執行緒盤點單一正式掛載磁碟上已識別的目前使用者 freedesktop 回收筒。兩次預設為「否」的詢問列出每組確切的 `files` 與 `info` 路徑、內容邏輯大小、頂層項目數與不可復原性。僅接受完整、權限私有、擁有者為目前 UID 且收據相符的範圍；範圍資料夾連結、其他擁有者、特殊項目、缺少／孤立收據、掛載邊界或超出盤點上限都會拒絕。移除前立即重新推導範圍並比對完整核准盤點。相對於已開啟目錄的描述元執行移除，不跟隨內容連結、不使用收據的原始路徑，並保留系統回收筒資料夾。變動項目會略過；同時變動或權限錯誤可能導致僅完成一部分，已移除數量與錯誤會保持可見。開始清空後停止／關閉不能中斷。容量／回收筒列表會更新，主畫面舊容量帳本會清除，重新掃描可更新既有樹狀圖。Linux 原生驗證僅使用私有掛載命名空間中的全新 ext4 映像，保持範圍外連結目標不變，不清空真實使用者回收筒。macOS 原生驗證仍待完成。

macOS 必須是與主要登入使用者相同的未提升權限 UID；root、已切換／未知使用者或提升權限的身分都會拒絕。家目錄取自帳戶記錄，不使用 HOME 覆寫。**清空所有已掛載磁碟的 Finder 回收筒…** 會檢視目前使用者的整個 Finder 回收筒，與選取哪一列無關。可取消的專屬背景工作向 Qt 取得所有已掛載根目錄，拒絕無法存取、遺漏或超出上限的盤點，並不跟隨連結地盤點目前 UID 的私有家目錄 `.Trash` 與已掛載 `.Trashes/<uid>`。實體範圍會去除重複，總中繼資料上限為 100,000 個項目／128 層；失敗時不允許確認。兩次預設為「否」的純文字詢問列出範圍、已掛載根目錄、內容邏輯大小／項目數與不可復原性。背景工作重新推導完整盤點並比對後，僅執行 `/usr/bin/osascript -e 'tell application "Finder" to empty the trash'`，不使用 shell 或插入路徑，並等待應用程式回應。Finder 影響所有已掛載回收筒，也可能移除作業期間新增的項目；開始清空後不能取消。自動化權限、系統錯誤或仍有內容／無法存取都會保持可見，並更新中繼資料；錯誤後 Finder 也可能仍在執行。主畫面舊容量帳本會清除；重新掃描可取得最新樹狀資料。測試使用可丟棄 POSIX 測試資料與模擬 Finder 執行，不清空真實使用者回收筒。由於沒有 Mac，原生 macOS 權限、APFS、多磁碟與 Finder 行為仍未驗證。

歡迎頁在每個就緒磁碟下顯示回收筒大小／項目數，清理頁顯示目前掃描所在磁碟。標示起初為 **尚未查詢**；**更新回收筒大小** 會在可取消的背景任務查詢唯讀快照（最多 256 個就緒根目錄，優先查詢掃描所在磁碟），移至回收筒後或關閉回收筒管理視窗也會更新。缺少範圍保持未查詢；部分失敗顯示 **總計未知**、已知大小／數量與純文字錯誤，不會當作空回收筒。POSIX 大小為內容的邏輯位元組，範圍可能重疊，請勿加總。大小單位與語言會隨設定更新。新的完整掃描會丟棄未完成回覆並重設清理頁範圍，關閉程式會等待查詢結束。這些標示不會產生清理建議或更改掃描記錄。

**檢視 → 磁碟總覽…** 或歡迎頁的 **磁碟總覽…** 列出最多 256 個就緒的已掛載磁碟與全部數量，包含檔案系統、總量／已用容量、可用空間長條、配置單位、資源回收筒大小與項目數。按兩下掃描根目錄；Ctrl+C 複製列。可停止的背景工作更新系統數值與查詢回收筒，不讀取內容、不修改項目。可用空間可能扣除保留量／配額；重複掛載可能共用容量，不能加總各列。Windows 叢集查詢失敗會保持未知，不採用掃描器的預估替代值。POSIX 單位使用檔案系統片段，不採用 Qt 的最佳傳輸區塊大小。Windows 回收筒總量來自 `SHQueryRecycleBinW`；Linux 涵蓋家目錄 freedesktop 回收筒與掛載根目錄的使用者回收筒，macOS 使用個人 `.Trash`／`.Trashes`。POSIX 大小為邏輯內容位元組，不含資料夾／收據中繼資料與共用配置；失敗顯示總量未知及已知大小。macOS 原生驗證仍待完成。停止／關閉會等待目前系統呼叫與背景工作，捨棄取消後回覆。清空回收筒是此唯讀總覽之外的功能。

**檔案 → 匯出 → 掃描報告（HTML／Excel）** 經可停止的模態背景工作儲存整份掃描記錄，不受目前篩選與圖表瀏覽位置影響。兩種格式皆含摘要／掃描範圍、最大資料夾、最大檔案、副檔名、分類與修改檔齡清單，標題顯示已列出／全部數量。最大資料夾範圍重疊；大小／數量保留原始位元組與數字，磁碟配置仍是估計值，範圍不完整時有標示。資料夾／檔案各保留 1,000 筆，副檔名限 10,000 筆。HTML 內嵌整份根目錄的矩形樹圖、長條圖與旭日圖 PNG 擷取，圖形範圍有限；沒有指令碼、外部資源或網路請求。Excel 每份清單各用一張工作表，含凍結標題與篩選，逸出公式樣式文字與 XML 控制字元，每格限 32,767 字元，16 位以上整數以精確文字儲存。成功原子取代前，停止／關閉保留既有目標。`openpyxl` 是安裝時包含的應用程式相依套件；產生報告不讀取原始檔案內容。

**檔案 → 專案與可重建資料…** 在可停止的背景工作查閱已掃描資料，保留最大的 1,000 個專案與管理儲存區，並顯示全部數量。已知邏輯大小分成 **來源／其他**、`.git` 與 **可重建資料**，另列已記錄的磁碟配置與掃描範圍。來源／其他包含未分類資料；巢狀專案範圍重疊，不能加總各列。Git 指標檔案不含外部中繼資料。Python／conda 環境標記與專案資訊檔共用清理的保守辨識規則，涵蓋環境、`node_modules`、Rust 輸出與專案內 Gradle 資料。按兩下在樹狀圖選取專案；Ctrl+C 複製列。**審查符合條件的可重建項目** 將最多 1,000 個項目送入既有資源回收筒審查流程，遵守最低年齡、掃描範圍、規則設定與排除條件。已停止的掃描不提供清理提案。產生資料可能含自訂檔案，需人工審查。獨立環境、Maven `.m2`、全域 Gradle 快取與 Docker 資料分開辨識，不假定可丟棄；不執行快取清除或 Docker 指令。

**檔案 → Git 歷史…** 以 `git rev-list --objects --all --no-object-names` 與 `git cat-file --batch-check` 查閱選取的工作資料夾（或選取檔案所在的資料夾），適合 `.git` 佔據專案主要空間時使用。可停止、限時 120 秒的背景工作保留最大 1,000 個可達物件的識別碼、類型與 **解壓後長度**，並顯示全部數量；有界管線避免將整份歷史存入記憶體。Ctrl+C 複製列。`git count-objects -v` 辨識 gc 可能整併的鬆散物件，但所有參照可達的物件會保留，實際節省量仍未知。保留 Git 擁有者檢查；停用選用鎖定、自動維護、檔案系統監視掛勾與延遲下載。不修改存放庫資料、不執行 gc，也不下載缺少的物件。需安裝支援 `--no-lazy-fetch` 的 Git；缺少或較舊版本會回報錯誤。Git 名稱提示可能有歧義且會改動換行，因此不列物件名稱。

樹狀清單上方的 **篩選已展開的資料夾…** 僅在已展開的資料夾下比對名稱，不分大小寫。可取消的背景查詢保留符合項目及其上層路徑，不搜尋摺疊的內容。清除方框即可恢復樹狀清單與展開狀態。從圖表／清單選取被隱藏的目標會清除篩選，以顯示目標。來源／代理索引對應保留選取、排序、持續索引及即時更新；總量、圖表與匯出仍使用完整掃描。

**檔案 → 比較兩個資料夾…** 以溫和背景工作獨立掃描兩個現有資料夾，顯示完全相符的相對路徑、僅左／右側有的項目、類型／大小／時間差異及兩側中繼資料。Unicode 與大小寫完全比對；不跟隨連結，無法讀取資料夾下的缺少項目仍為未知。中繼資料相同仍是 **尚未驗證內容**。選取檔案對後按 **驗證選取的內容**，可停止完整雜湊驗證，並以快照防止變更造成誤判；變更、讀取錯誤與已知雲端預留位置保持無法驗證。雜湊結果對應驗證當時。Ctrl+C 與原子 CSV 匯出涵蓋顯示的列（最多 10,000 列，並顯示全部數量及不完整範圍）。比較為唯讀，不提供同步動作。

**檔案 → 雲端與特殊檔案…** 在可停止的背景工作查閱已記錄中繼資料，顯示最大的 1,000 個符合項目及全部符合項目的數量／總量。召回／離線屬性可能來自 OneDrive、Dropbox 或其他服務，提供者與本機內容比例未知。**完整內容大小** 是含線上內容的邏輯長度，下載後的配置仍未知。清單也辨識 Windows 壓縮／稀疏屬性；沒有屬性卻配置較少時，原因保持未知（可能是稀疏、壓縮或常駐資料）。召回／離線的配置 0 是掃描估計。畫面顯示不完整範圍及無法取得的中繼資料，不開啟／下載內容，也不增加每個掃描項目的欄位；支援排序、Ctrl+C 及按兩下選取樹狀清單中的項目。

Windows 可用 `python tools/measure_streams.py <folder> --entries 10000 --repeats 5` 獨立量測 NTFS 替代資料串流。工具先計時掃描整個資料夾，再對有限數量的檔案與資料夾查詢額外中繼資料，輸出 JSON。排除重新解析點，失敗保持未知，不開啟串流內容；串流長度是邏輯位元組，不是磁碟配置。2026-10-07 原始碼資料夾樣本的 9,749 個項目皆未發現替代串流；額外查詢耗時 1.694 秒，一般掃描 0.466 秒（五次中位數，含每項目兩次識別檢查）。這個樣本不能代表整碟出現比例；一般掃描維持原有行為。

Windows 可用 **選項 → 檔案總管整合…**，在自己帳號的檔案總管資料夾選單新增或移除 **使用 FileTree 掃描**（Windows 11：**顯示其他選項**）。儲存前不會啟用，不需要系統管理員權限，且不會覆寫或移除沒有專屬標記的登錄項目。移動執行檔或原始碼資料夾後，請重新登錄。命令使用加上引號的絕對啟動路徑，因此原始碼版本也可從檔案總管的工作目錄啟動。Windows 上的 FileTree 項目右鍵選單也提供原生 **內容** 對話方塊。

- **按一下就開始**：選一個資料夾、按一下磁碟、把資料夾拖曳到視窗上，或貼上路徑。
- **平行、邊掃邊看**：同時讀取多個資料夾；兩個工作執行緒記錄檔案身分時，約 202 萬筆的 Windows 系統碟耗時 208 秒。掃描時資料夾樹就會陸續出現，最大的資料夾排在最前面；按停止會留下已經讀到的部分。
- **資料夾樹**：由大到小排列，每一列有它實際佔用的磁碟空間、顯示它佔所在資料夾比例的長條，還有檔案數、資料夾數與裡面最近一次變動的時間。
- **圖表**，四種看資料夾的方式，在分頁角落切換（一開始是方塊圖）：**方塊圖**（每個檔案一個方塊，大小代表佔用的空間；資料夾裡小到看不見的檔案合成一個斜線方塊）、**長條圖**（資料夾裡每個項目一條長條，由大到小，附大小與比例）、**放射圖**（目前資料夾在中心，每深一層就是外面一圈）和**樹狀圖**（可展開的資料夾分支，每張卡片附大小與比例）。按一下可以在資料夾樹中找到它，按兩下可以聚焦資料夾，四種圖會一起跟著。
- **最大的檔案**：整個掃描範圍內最大的 1,000 個檔案，附篩選框。
- **搜尋**（Ctrl+F）：依名稱，或 `*.mp4` 這類樣式，在整個掃描範圍內找檔案和資料夾。
- **清理**：列出通常可以刪掉的東西——暫存檔、瀏覽器快取、當機傾印檔、套件快取、可以重新建置的編譯產物、下載資料夾裡的舊安裝檔、空資料夾——依種類分組，並說明刪掉各種東西的影響。
- **重複檔案**（在「清理」裡）：把內容相同的檔案分組，並顯示多餘的副本佔了多少空間；明確選擇保留副本後，即可選取多餘的副本並移到資源回收筒。
- **與先前的掃描比較**：把掃描存成 JSON，之後就能看出哪些資料夾變大、變小、新增或消失。
- **檔案類型**與**檔案新舊**：依副檔名與種類（圖片、影片、壓縮檔…），以及依最後修改時間統計佔用的空間；按兩下一列就列出它最大的檔案。
- **安全地釋出空間**：「移到資源回收筒」每次都會先詢問，不會永久刪除；移動前會在背景核對項目，之後重新掃描受影響的資料夾。
- **匯出**資料夾清單或最大的檔案成 CSV（可用 Excel 開啟），或把資料夾樹匯出成 JSON。
- **English、繁體中文、简体中文**，隨時切換；內建「使用說明」。
- 連結與目錄連接會列出來，但不會跟進去計算，所以不會重複計算，連結形成的迴圈也不會讓掃描停不下來。無法讀取的資料夾列在「無法讀取」分頁，不會中斷掃描。

## 安裝

FileTree 可在 Windows、macOS 與 Linux 上執行。

**Windows，不需要 Python**：從 [Releases](https://github.com/JeffreyChen-s-Utils/FileTree/releases) 頁面下載 `FileTree-<版本>.exe` 直接執行，不必安裝。

從下一次發版起，同一頁也會提供 `FileTree-<版本>-windows-standalone.zip`。解壓縮**整個資料夾**後執行其中的 `FileTree.exe`，啟動較快；DLL、外掛及翻譯檔都要保留在旁邊。單檔 EXE 較方便攜帶，但每次啟動都會先解壓縮內含檔案。兩種形式都不需要 Python。

**有 Python 3.10 以上**，從 PyPI 安裝：

```bash
pip install je_file_tree
je-file-tree
```

或從原始碼執行：

```bash
git clone https://github.com/JeffreyChen-s-Utils/FileTree.git
cd FileTree
pip install -r requirements.txt
python start_file_tree.py
```

`python -m je_file_tree` 的效果相同。

### 編譯成獨立程式

要把 FileTree 給沒有安裝 Python 的人使用，可以用 Nuitka 編譯成程式資料夾或單一 `.exe`：指令與每個選項的用途請見 [nuitka.zh-TW.md](../nuitka.zh-TW.md)。

## 使用方式

1. **選擇要掃描的地方**：在起始頁按「選擇資料夾…」或其中一顆磁碟、把資料夾拖曳到視窗上，或在上方的方框輸入路徑後按 Enter。也可以從命令列直接開始掃描：`je-file-tree D:\Projects`（或 `python start_file_tree.py D:\Projects`）。
   拖曳資料夾會在原位置掃描，且只接受複製動作；即使用 Shift 要求移動，也會保留來源。
2. **邊掃邊看**：資料夾樹會立刻出現，FileTree 一邊加總，最大的資料夾一邊往上排；最大的檔案與檔案類型在掃描結束時補上。隨時可以按「停止」（或 Esc）結束掃描，已經讀到的部分會留下來並標示為不完整。
3. **找出佔空間的東西**：最大的資料夾排在最上面。按資料夾旁的箭頭看裡面的內容，或在右邊的圖表裡瀏覽。

### 看懂結果

| 位置 | 告訴你什麼 |
|---|---|
| 資料夾樹 | 大小、「磁碟大小」（實際佔用的空間：以整個叢集計算，通常比大小多一點；壓縮檔案較少，只存在雲端的檔案是 0）、「佔上層比例」（佔上一層資料夾的比例）、裡面的檔案數與資料夾數、最近一次變動的時間 |
| 圖表 | 「方塊圖」：每個檔案一個方塊，大小代表佔用的空間；每個資料夾頂端有名稱與大小。太小的檔案合併成灰色斜線方塊。「層數」決定顯示深度，「顏色」可依檔案類型或資料夾上色。「長條圖」：目前資料夾裡每個項目一條長條，附大小與比例。「放射圖」：目前資料夾在中心，每深一層就是外面一圈；按中心回上一層。「樹狀圖」：資料夾卡片附磁碟佔用大小與佔父資料夾的比例；按加號展開分支，按「其餘資料夾」載入更多，可切換左右或上下方向、按 Ctrl＋滾輪縮放並用捲軸移動。按兩下資料夾聚焦，按「上一層」回去；四種圖永遠顯示同一個資料夾，FileTree 會記住選取的圖表與樹狀圖方向 |
| 最大的檔案 | 最大的 1,000 個檔案；在篩選框輸入文字可以縮小清單，按兩下可以在資料夾樹中找到那個檔案 |
| 搜尋 | 名稱含有輸入文字的檔案和資料夾；樣式（`*.mp4`）要符合完整名稱，好幾個樣式用 `;` 分開（`*.iso;*.zip`）；搜尋框下方的條件可以縮小範圍，也可以單獨使用：大於或小於某個大小、最近一週／一個月／一年內改過或超過一、二、五年沒動、檔案類型、只有檔案或只有資料夾；搜尋可以取名儲存，之後再選回來；列出最大的 1,000 個符合項目，並顯示全部的數量和總大小 |
| 清理 → 建議 | 內建規則須符合檔齡與路徑／專案依據，提示會說明風險與重建方式。不確定群組須手動審查，預設不勾選；較低風險快取可整批送審，套件儲存庫不列入。「選項 → 清理政策」控制規則、檔齡及獨立的排除項目 |
| 清理 → 重複檔案 | 以開頭／完整雜湊找出相同大小的檔案（硬連結只算一份），預設最低 1 MB。每組明確選擇保留副本，核對路徑與估計，再選取已核對的多餘副本供 Delete。已變更、受保護、未驗證及硬連結群組保持原樣 |
| 檔案類型 | 每種副檔名佔用的空間；在表格上方選一種類型就只顯示那一類，按兩下一列會列出那種檔案裡最大的幾個 |
| 檔案新舊 | 依最後修改時間（一個月內……超過 2 年）統計佔用的空間；按兩下一列會列出那一段裡最大的檔案 |

### 釋出空間

在任何項目上按右鍵，可以開啟它、在檔案總管中顯示、複製路徑、在圖表中顯示、在 FileTree 以外改過東西之後重新掃描這個資料夾（其餘結果不變）、只掃描這個資料夾，或移到資源回收筒（macOS 與 Linux 是「垃圾桶」）。要一次移走好幾個項目，在資料夾樹、「最大的檔案」或「搜尋」清單裡用 Ctrl+按一下或 Shift+按一下選取，只會詢問一次，並列出它們和總大小。FileTree 移動任何東西之前都會先詢問，而且不會永久刪除。系統與程式的資料夾（Windows 資料夾、Program Files、AppData 裡的程式設定、使用者的個人資料夾，以及 macOS 與 Linux 上對應的位置）會說明原因並多問一次；暫存資料夾與快取不會，因為那正是要清理的東西。

移動每個項目前會核對掃描記錄的檔案身分、種類、大小、時間、目前上層路徑、解析後的保護狀態與資料夾內容。已變更、不存在或掃描不完整的項目會略過並說明原因；移動、略過與失敗分別計數。「停止」可取消剩餘項目；完成後會重新掃描受影響的上層資料夾。狀態列顯示移動容量，清空資源回收筒後才增加可用空間。記錄檔案身分會增加掃描時間與記憶體，Windows 尤其明顯。

移動失敗時，背景診斷會列出觀察到開啟檔案的程式及 PID（Windows Restart Manager 或 Linux `/proc`），不會自動關閉程式。資料夾診斷最多查詢 256 個已掃描檔案；無法存取的行程、資料夾控制代碼及其他失敗原因可能未知，觀察到占用程式也不能證明它就是失敗原因。

按「選取這一組」或「全部選取」會在確認移動前開啟審查佇列，逐項顯示路徑、規則、原因、日期、邏輯與配置大小、保護狀態及移除後果；表格下方會顯示選取項目的完整說明。可以取消勾選以保留項目，或開啟所在資料夾。上層與子項重複選取時只保留最外層。背景估計會把硬連結的共用配置空間只算一次，仍有其他名稱的檔案不列為可回收資料。清空資源回收筒後可回收的檔案資料以保守範圍呈現，共用區塊及資料夾中繼資料仍未知。

「**檔案 → 最近操作**」顯示最近 500 個已確認的操作，包含移動、略過與失敗。日誌只記錄時間、原始路徑、磁碟／檔案身分、理由、結果，以及 Qt 提供的資源回收筒位置，從不儲存檔案內容。僅追加的 JSONL 區段以原子方式寫入應用程式本機資料目錄的 `journal/`，保留 90 天／50 MB。先記錄確認才執行操作；無法記錄時略過移動。結果寫入失敗時會盡可能停止剩餘移動，並提示紀錄可能不完整。中斷後只有確認紀錄的操作，其最終結果未知。CSV 匯出會將家目錄前綴替換成 `{HOME}`；記錄資源回收筒位置不保證可還原。保留管理只移除 FileTree 自有的日誌區段，不會移除掃描的檔案。

規則會說明分類、依據、最低檔齡、風險與重建方式。近期或無日期項目不列入，資料夾依最新的子項計算（快取／建置／暫存／空資料夾 7 天、套件下載／當機傾印 30 天、安裝檔 90 天）。瀏覽器個人設定、套件儲存庫（`.m2/repository`、`.nuget/packages`、`.gradle/caches`）及僅名稱像快取／建置的資料夾不列入。專案輸出須有專案描述檔，Python 快取須有產生檔案的依據。暫存、當機證據、下載、建置輸出及空資料夾使用「手動審查」，預設不勾選且不包含在「全部選取」中。較低風險的快取仍須審查與確認。

「**選項 → 清理政策**」可啟用／停用每條規則、設定最低檔齡，或排除絕對路徑／名稱樣式（每行一個）。排除子項也會避免把其上層資料夾整個列入。這與「掃描時略過」獨立：不提出清理建議的資料仍計入磁碟用量。未修改時保留內建規則。儲存前會依目前掃描預覽增加／移除的候選數量與邏輯容量，修改設定會使預覽失效。政策儲存在 QSettings，僅接受經驗證的第 1 版 JSON 匯入（支援的規則、布林開關、0–36500 天與排除項目）。已儲存的設定無效時會停用建議，直到重新審查；手動審查風險不能調低，也不支援自行執行的規則。

### 看看哪裡變大了

「**檔案 → 掃描歷史…**」顯示此根目錄保留的容量折線圖及最多 1,000 筆掃描。選取先前掃描即可開啟既有的「變化」分頁，不必選擇檔案；Ctrl+C 可複製列。歷史預設啟用，**所有根目錄合計上限 1 GiB**。「**選項 → 掃描歷史設定…**」可停止未來儲存或調整上限（1–16384 MiB），降低上限會在下次儲存時套用；關閉後仍可讀取既有歷史。整棵掃描將資料夾路徑、名稱、容量與涵蓋範圍，以相容的掃描 JSON 存入應用程式本機資料目錄的 `history/<root-path-hash>/`，不含檔案內容。停止的掃描及局部重掃不儲存；含讀取錯誤的完成掃描標示為不完整，缺少資料夾不代表已刪除。依名稱計算的配置量分別計入硬連結名稱，比較描述中繼資料而非驗證內容。只從所有根目錄依時間移除辨識為歷史的中繼資料，以符合上限；拒絕連結目錄、連結檔案及其他資料。單筆快照超過上限時會略過並顯示錯誤，掃描仍可完成。儲存／讀取失敗會顯示；停止或關閉會等待背景讀取結束。歷史僅存本機，不排程掃描，也不移除記錄中的來源檔案。

用「**檔案 → 匯出 → 資料夾樹（JSON）**」把掃描存起來。之後重新掃描，選「**檔案 → 與先前儲存的掃描比較…**」開啟那個檔案，就會出現「**變化**」分頁，列出每個有變化的資料夾之前和現在的大小，變大最多的排在最前面；新的資料夾標示「新增」，消失的標示「已不存在」。在按「結束比較」之前，之後的重新掃描都會繼續比較。資料夾是依它在掃描資料夾底下的路徑對應，所以也可以拿來跟放在別處的同一份資料（例如備份）比較。

### 小知識

- 大小是檔案的實際大小，以二進位單位計算（1 KB = 1,024 位元組），和 Windows 檔案總管相同；可以在「檢視 → 大小單位」改用固定的單位。
- 在 Windows 上，FileTree 啟動時會像 TreeSize 一樣要求系統管理員權限，受保護的資料夾也能讀取。拒絕的話它照常以一般權限執行，讀不到的資料夾列在「無法讀取」分頁，那裡有「以系統管理員身分重新啟動」按鈕（「檔案」選單裡也有）。不想每次被問，可以關掉「檢視 → 啟動時要求系統管理員權限」。
- 「最大的檔案」、「檔案類型」與「檔案新舊」預設統計整個掃描範圍；按這幾個分頁右上角的「只看選取的資料夾」，就會改為跟著資料夾樹中選取的資料夾。
- 預設會計算隱藏檔案；關掉「檢視 → 包含隱藏檔案」，下次掃描就不會算進去。
- 清理建議會顯示已知容量，以及略過、無法讀取、尚未掃描的資料夾數；省略部分的容量為未知。不完整的分支不會被整個建議清理，也不會被視為空資料夾。掃描不完整時停用「全部選取」；清理前請重新掃描相關分支。更新時會清掉過期建議。
- 要讓某些資料夾每次都不掃描，把它們加進「檢視 → 掃描時略過」：像 `node_modules` 或 `*.cache` 這樣的名稱會略過所有同名的資料夾，路徑只略過那一個資料夾。略過的資料夾會以灰字列出，大小為 0。
- 語言、大小單位、視窗配置與最近掃描過的資料夾都會記住（Windows 上存在登錄檔的 `HKEY_CURRENT_USER\Software\JE-Chen\FileTree`）。

重複檔案的總量標為「邏輯大小」。每組請選取檔案列並按「保留選取的副本」，清單會標示保留副本的完整路徑，並保留名稱、日期與上層資料夾供比較。估計依這些選擇顯示不重複配置空間及清空資源回收筒後可回收資料的保守範圍，未決定的群組保持未知。「選取多餘的副本」只包含範圍、保護狀態、變更與硬連結名稱（含掃描範圍外的名稱）核對成功的群組。確認後會重新完整雜湊並核對該組所有檔案；核對失敗時整組保持原樣並要求重新掃描。「停止」取消剩餘工作。系統移動失敗仍可能造成部分批次完成；資源回收筒移動不是整組原子操作。壓縮／稀疏檔案依配置大小計算，雜湊不開啟已知的雲端佔位檔。共用區塊及資料夾中繼資料仍未知，移到資源回收筒本身不釋放空間。隔離磁碟實測仍待完成。

相同資料夾會列在檔案群組上方，以「副本 = 原始資料夾」顯示，沿用搜尋所得的雜湊，不會再讀取內容。每個非空檔案都須有已驗證雜湊，且相對名稱、大小、雜湊與空資料夾結構須相同。未雜湊的小檔案／獨有檔案、連結及不完整分支會阻止資料夾配對。已包含在上層配對中的子項不重複列出，其他位置的額外副本仍會列出。這些列僅比對搜尋快照，不代表可移除資料夾。

### 容量明細

Windows 的「**檔案 → 已安裝程式…**」列出最多 1,000 個解除安裝登錄項目及辨識到的 Steam／Epic 遊戲名稱，並顯示完整數量及中繼資料失敗情況。唯讀查詢 HKLM／HKCU 的 32／64 位元檢視，不修改登錄資料庫。`EstimatedSize` 是回報的 KiB 估計；資料夾邏輯／配置量只取自目前掃描中完全相符且不是連結的資料夾。缺少位置及無法讀取／略過範圍保持未知或不完整。Steam 清單取自掃描中的 `steamapps`，也會讀取 Epic 固定的 `%PROGRAMDATA%/Epic/EpicGamesLauncher/Data/Manifests`，可核對另一磁碟的遊戲名稱。每份清單限 1 MiB，核對掃描及開啟檔案的快照，略過已知雲端／連結狀態，並回報格式錯誤或變更。共用／巢狀安裝資料夾可能重疊，請勿加總列或推算解除安裝可釋放空間；部分封裝／可攜式應用程式不會列出。按兩下選取相符的樹狀資料夾，Ctrl+C 複製列。按鈕以固定 URI 開啟 Windows 已安裝應用程式設定，不執行登錄項目的解除安裝命令。停止或關閉會等待背景工作結束並忽略取消的回覆。此檢視僅限 Windows。

帳本也會辨識絕對路徑的自訂 `XDG_DATA_HOME/Trash`；相對路徑設定會使用預設資料目錄。

資料夾樹上方會顯示系統已用／可用空間，以及硬連結只算一次的檔案配置估計。「容量明細」會區分依名稱計算的配置、硬連結重複量、已讀取的資源回收筒資料（已包含）、略過／無法讀取的範圍及其他掛載磁碟。完整掃描整個磁碟時，會把無法解釋的差額列為「未能歸帳」。僅掃描資料夾、掃描不完整、缺少識別資訊或配置估計超過系統已用空間時，都無法核對整個磁碟。檔案系統中繼資料／保留空間、略過的位元組及其他磁碟的總量保持「未知」，而非 0。系統容量與檔案快照不是同時量測，共用區塊、快照與 Windows 配置估計會影響差額；自建 ext4 容量／保留空間及硬連結／稀疏檔案回收案例已通過 CI；NTFS／APFS 與共用區塊仍待驗證，因此帳本只稱為估計。Linux 資源回收筒的邏輯內容量，與帳本含內容及收據的配置量範圍不同，皆不是額外加計的容量。命令列的掃描記錄也會在 `capacity` 欄位包含這些數字。跨磁碟的資料夾掛載點只列出、不繼續掃描。Linux 也會在遍歷前及回傳結果前讀取 `/proc/self/mountinfo`，略過明確的資料夾掛載點，包含同裝置 bind mount 及經祖先別名到達的路徑。掛載邊界列在「無法讀取」，略過位元組保持未知；直接選取掛載資料夾作為掃描根目錄仍可掃描。掛載表遺失或格式錯誤時，會在遍歷前停止。其他 POSIX 系統仍採裝置邊界偵測。Linux 會在讀取項目中繼資料期間保持資料夾描述元開啟，檢查掛載 ID 與原先識別資訊；相關掛載點或根目錄掛載變更時，拒絕回傳成功結果，請依錯誤提示重新掃描。失敗掃描不寫入歷史；選取範圍之外的掛載變更不會中止掃描。Linux 需要可讀取且含掛載 ID 的 proc 中繼資料（核心 3.15 以上）。核心 5.8 以上且 libc 支援時，使用經結果旗標確認的 statx 描述元查詢，避免每個資料夾額外開啟與解析 proc 檔案；不支援、拒絕或缺少結果時改讀 fdinfo。這仍不是檔案系統交易快照。私有 Linux 命名空間的自建靜態同裝置 bind mount 已通過 CI；CI 也測試開啟資料夾前後的即時 bind mount，並記錄描述元防護的耗時。

在資料夾樹的欄位標題按右鍵，可選擇顯示的欄位，設定會保留。名稱欄保持顯示並預設為可讀寬度，額外欄位可水平捲動。「**占磁碟比例**」可選擇顯示，與「占上層比例」並列，依邏輯位元組除以系統回報的磁碟總容量。容量尚未取得、資料夾樹變更後及其他磁碟項目會顯示未知；硬連結名稱仍分別計算，因此不是配置或可回收空間。

## 不開視窗的命令列

命令列入口只使用核心，不會載入 Qt。CSV／JSON 匯出與視窗相同，以原子方式寫入；比較會列出絕對變化最大的項目，最多 `--limit` 筆（預設 1,000）。標準輸出是逐行 JSON，使用固定欄位（`file-tree-cli/1`）並包含掃描涵蓋範圍；比較會增加 `changes` 記錄。錯誤以 JSON 寫到 stderr。預設兩個工作執行緒，可用 `--workers`、可重複的 `--exclude` 樣式及 `--no-hidden` 控制掃描。

```bash
je-file-tree-cli scan D:\ --folders folders.csv --largest largest.csv --json tree.json
je-file-tree-cli scan D:\ --compare old.json --limit 20
python -m je_file_tree.cli scan D:\ --exclude node_modules --workers 2
python -m je_file_tree.cli scan D:\ --count-hard-links
```

結束代碼：**0** 涵蓋範圍完整、**1** 不完整（包含排除及無法讀取的項目）、**2** 參數錯誤、**3** 掃描／比較／匯出 I/O 錯誤或儲存的掃描格式無效、**130** 已中斷。Ctrl+C 會停止掃描並匯出已讀取的部分；再次按 Ctrl+C 則立即中止。每份匯出獨立完成原子寫入，後續匯出失敗不會撤銷先前完成的報告。命令列不提供移除或自動清理。

## 開發

Python 整合請參閱[核心 API 指南](../docs/core-api.md)：公開匯入路徑、掃描／搜尋／重複檔案／比對範例、取消、原子匯出及配置空間限制。核心不會匯入 Qt。

```bash
pip install -r dev_requirements.txt
python -m pytest
python -m ruff check .
python tools/make_screenshots.py
```

`tools/make_screenshots.py` 會用一個虛構的資料夾重新繪製 README 裡每種語言的圖片。程式架構、主要流程與設計規則寫在 [architecture.md](../architecture.md)。

整碟掃描可以設定資源預算後量測（預設兩個工作執行緒、512 MB、180 秒）。因預算而停止的掃描會在報告標為不完整；重複檔案雜湊另有時間限制。CSV 與 JSON 匯出以串流寫入暫存檔，再取代目的檔案，大型掃描也不必在記憶體保留另一份匯出資料。

```bash
python tools/measure_scale.py C:\ --gui --memory-mb 768 --duplicates-seconds 10 --output scale.json
```

Linux 桌面 CI 檢查使用全新容器、Xvfb／X11 與獨立工作階段匯流排，驗證嚴格的 `ShowItems(as, s)` 服務、專用測試檔案的完整垃圾桶流程、匯流排斷線時透過記錄用 `xdg-open` 開啟資料夾的備援，以及原生繁體中文字型繪製。失敗時也保存紀錄、證明 JSON 與截圖；產物不完整即判定失敗。專案唯讀掛載，執行限制為 1 GB 記憶體及兩個 CPU。可在已啟動 Docker 的 Linux shell 重現：

```bash
docker build --build-arg DESKTOP_UID="$(id -u)" --build-arg DESKTOP_GID="$(id -g)" -t filetree-desktop-probe -f tools/linux_desktop/Dockerfile .
mkdir -p desktop-evidence
docker run --rm --user "$(id -u):$(id -g)" --memory=1g --cpus=2 -v "${PWD}:/workspace:ro" -v "${PWD}/desktop-evidence:/evidence" filetree-desktop-probe
```

bind mount，並測試開啟資料夾前後新增掛載。也量測 1,001 個資料夾、2,000 個檔案的描述元防護
與一般路徑讀取耗時。只移除剛建立的拋棄式測試資料，拒絕既有磁碟與使用者的資源回收筒。JSON 證據保留
